# Массовый импорт услуг

Скрипт для заливки каталога категорий + услуг в API AIDA одним запуском.

## Файлы

- `services-catalog.json` — данные (категории + услуги). Можно править перед запуском.
- `import-services.ps1` — PowerShell-скрипт, который читает JSON и вызывает API.

## Что делает скрипт

1. Получает список существующих категорий и услуг из API.
2. Для каждой категории из JSON:
   - если её ещё нет (сравнение по имени, регистронезависимо) — создаёт через `POST /services/categories` с `isActive: true`;
   - если есть — использует существующий `id`.
3. Для каждой услуги внутри категории:
   - если услуга с таким **именем + аудиторией** уже есть — пропускает;
   - иначе создаёт через `POST /services` со всеми полями (`name`, `defaultDurationMin`, `defaultPrice`, `categoryId`, `audience`).
4. В конце печатает сводку: сколько создано / пропущено / с ошибками.

Скрипт **идемпотентен** — можно запускать несколько раз, повторные запуски не создадут дубликатов.

## Требования

- PowerShell 5.1+ (встроен в Windows 10/11) или PowerShell 7.
- JWT токен пользователя с ролью **OWNER**, **ADMIN** или **DEVELOPER**.

## Запуск

### Обычный владелец (OWNER / ADMIN)

```powershell
cd C:\Users\Hukum\Desktop\AIDA\scripts
./import-services.ps1 `
    -ApiUrl  "https://api.yourdomain.kz" `
    -Token   "eyJhbGciOiJIUzI1NiIsInR..."
```

### Разработчик (DEVELOPER) — обязательно указать организацию

```powershell
./import-services.ps1 `
    -ApiUrl         "https://api.yourdomain.kz" `
    -Token          "eyJhbGciOi..." `
    -OrganizationId "org_abc123def45"
```

### Свой JSON

```powershell
./import-services.ps1 -ApiUrl "..." -Token "..." -CatalogPath "./my-services.json"
```

## Где взять токен

1. Открой фронтенд, залогинься.
2. DevTools → Network → любой запрос к API → заголовок `Authorization: Bearer <TOKEN>` → скопируй значение без `Bearer `.

## Структура JSON

```json
{
  "categories": [
    {
      "name": "Воск прайс",
      "audience": "WOMEN",
      "services": [
        { "name": "Подмышки воск", "price": 2000, "duration": 10 }
      ]
    }
  ]
}
```

- `audience` на категории — задаёт аудиторию по умолчанию для всех её услуг (`WOMEN` / `MEN`).
- `price` — целое число тенге.
- `duration` — длительность услуги в минутах.

## Что вошло в текущий `services-catalog.json`

Все услуги из сообщения пользователя, сгруппированы по категориям со скриншота + две новых:

| Категория | Аудитория | Услуг |
|---|---|---|
| Skin's прайс | WOMEN | 5 |
| Воск прайс | WOMEN | 20 |
| **Электроэпиляция** (новая) | WOMEN | 9 |
| **Электроэпиляция муж** (новая) | MEN | 2 |
| Прайс шугаринг | WOMEN | 75 (25 позиций × Топ/1к/2к) |
| МУЖСКОЙ ПРАЙС ШУГАРИНГ | MEN | 22 |
| SKIN's ДЛЯ МУЖЧИН | MEN | 4 |
| ВОСК ДЛЯ МУЖЧИН | MEN | 10 |
| ЛАЗЕРНАЯ ЭПИЛЯЦИЯ ДЛЯ МУЖЧИН | MEN | 18 |

## Важные замечания по данным

1. **Электроэпиляция (женская)** — в исходных ценах было три варианта «1 час» (10800 / 13200 / 18000тг) и три варианта «2 часа» (21600 / 26400 / 36000тг). Так как исходно не было названий тарифов (Топ/1к/2к), в JSON они названы по цене: `Электроэпиляция 1 час (10800тг)` и т.д. После импорта переименуй их на UI под свои тарифные сетки (например, Топ / 1к / 2к).
2. **«Подборок воск», «Подборок Топ/1к/2к»** — исправлены опечатки на «Подбородок».
3. **«Щеки»** — везде использовано «Щёки».
4. **Длительности в «Прайс шугаринг»** — оставлены ровно как в исходном списке. Там есть странные места (например, «Спина полностью» со временем 10 минут — вероятно опечатка в исходнике; исправь на UI при необходимости).
5. **«Материал электро», «Обезбол электро»** — это не процедуры, а расходники / доп. опции. Они созданы как услуги с длительностью 1 минута и ценой = стоимости. Если у тебя под это другой механизм (например, «Товары» или «Допродажа»), их можно пропустить — удали из JSON перед запуском.

## После импорта

- Услуги попадают в каталог организации и по умолчанию доступны во всех филиалах сети.
- Если нужно в конкретных филиалах отключить что-то — используй `PATCH /services/:id/studio-offering` или `PATCH /services/categories/:id/studio-offering` (через UI — переключатели «Сеть» / «Филиал»).
- Если что-то создалось не так — категорию можно удалить через `DELETE /services/categories/:id`, услугу — `DELETE /services/:id` (удаление услуги запрещено только при активных записях BOOKED/ARRIVED).
