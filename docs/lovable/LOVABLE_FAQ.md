# FAQ организации — промпт для Lovable

Задача: реализовать в админке раздел «FAQ» для настройки публичного FAQ организации, который потом рендерится на лендинге (лендинговая часть — следующий этап, здесь только админка).

## Бизнес-контекст

- FAQ редактирует **владелец сети** (OWNER), **заместитель владельца** (DEPUTY_OWNER), **маркетолог** (MARKETER) и **разработчик платформы** (DEVELOPER). Остальные роли (ADMIN, MANAGER, MASTER, SERVICE) в этот раздел не пускай — скрывай пункт в навигации и страницу отдавай с 403, если зашли напрямую по URL.
- Роль **MARKETER** — новая, добавлена в enum `UserRole` (миграция `20260420130000_user_role_marketer`). В интерфейсе управления персоналом нужно добавить её в выпадашку ролей рядом с MANAGER / ADMIN. Это роль уровня сети (без привязки к филиалу), как DEPUTY_OWNER / MANAGER / SERVICE — отображать её в списке сетевого персонала (`GET /studios/:id/users/network`). Создавать/удалять MARKETER могут все, кто и обычного менеджера (OWNER, DEPUTY_OWNER, DEVELOPER). Подпись в UI — «Маркетолог».
- FAQ общий на всю организацию (одна сеть = один FAQ). Хранится на уровне Organization.
- Изначально список пустой, заполняется вручную. Никакого автосида.
- У каждого элемента: вопрос, ответ (Markdown), категория (тег для группировки, опционально), флаг «опубликовано», порядок сортировки (drag-and-drop).
- Черновики показываем только в админке. На лендинге видны лишь опубликованные.

## Куда положить в UI

- В главное меню админки добавь пункт **«FAQ»** рядом с существующим «Маркетинг» / «Промоакции» / «Мастера на лендинге». Иконка — вопросительный знак в круге.
- Пункт виден **только** OWNER, DEPUTY_OWNER, MARKETER и DEVELOPER. Остальным — не показывать.
- Страница делится на:
  1. Хедер «FAQ организации» + короткое пояснение (см. ниже).
  2. Кнопку «+ Добавить вопрос» (primary).
  3. Список элементов (см. ниже).

### Короткое пояснение в хедере

> Вопросы и ответы для публичного лендинга сети. Черновики видны только здесь, в админке. Опубликованные — попадают на сайт. Порядок можно менять перетаскиванием.

## API

Базовый URL — как у остального бэкенда (тот же хост, что `/landing/promotions`). Авторизация — Bearer JWT владельца.

### `GET /admin/faq`

Админский список: **все элементы**, включая черновики.

- Заголовки: `Authorization: Bearer <jwt>`.
- Query-параметры: для DEVELOPER опционально `?organizationId=<id>` — работать с чужой организацией. OWNER не передаёт, организация берётся из JWT.
- 200 — массив:

```json
[
  {
    "id": "ofq_a1b2c3d4e5",
    "organizationId": "org_xxx",
    "question": "Как отменить запись?",
    "answer": "Запись можно отменить **не позднее чем за 2 часа**…",
    "category": "Запись",
    "isPublished": true,
    "sortOrder": 10,
    "createdAt": "2026-04-19T20:13:58.000Z",
    "updatedAt": "2026-04-19T20:13:58.000Z"
  }
]
```

Пустой массив `[]` — нормально, это пустой FAQ.

### `POST /admin/faq`

Создать элемент. Тело:

```json
{
  "question": "Как отменить запись?",
  "answer": "**Не позднее чем за 2 часа** до её начала…",
  "category": "Запись",
  "isPublished": true,
  "sortOrder": 10
}
```

- `question` — обязательно, 1..500 символов после trim.
- `answer` — обязательно, Markdown, 1..10000 символов после trim.
- `category` — опционально, 0..64 символов, пустая строка → `null`.
- `isPublished` — опционально, по умолчанию `true` (сразу виден на лендинге). Если владелец хочет сохранить черновик — переключить на `false` перед сохранением.
- `sortOrder` — опционально. Если не передан, бэкенд ставит элемент в конец (`max(sortOrder) + 10`).

Ответ 201 — созданный объект со всеми полями.

### `PATCH /admin/faq/:id`

Частичное обновление. Любое из полей из DTO выше, плюс можно присылать только одно изменённое.

- `category: ""` или `null` — очистить категорию.
- 200 — обновлённый объект.
- 404 — элемент не из этой организации / не найден.

### `DELETE /admin/faq/:id`

Удалить. Подтверждение делай на фронте модалкой. Ответ `{ "ok": true, "id": "ofq_..." }`.

### `PATCH /admin/faq/reorder`

Массово обновить порядок (drag-and-drop):

```json
{
  "items": [
    { "id": "ofq_a1", "sortOrder": 10 },
    { "id": "ofq_b2", "sortOrder": 20 },
    { "id": "ofq_c3", "sortOrder": 30 }
  ]
}
```

- Присылаем финальный порядок **всех видимых элементов** одним запросом, по шагу 10 (чтобы было куда вставлять между ними при следующем drag).
- В ответе возвращается **весь обновлённый список** (как `GET /admin/faq`) — используй его для обновления стейта, не полагайся только на оптимистичное обновление.

### `GET /landing/faq?organizationId=<id>`

(Для справки — лендинговая часть, админке не нужна.) Публичный эндпоинт, возвращает **только опубликованные**, в правильном порядке. Если админка открыта с токеном — `organizationId` можно не передавать, бэкенд возьмёт из JWT.

## UI админки

### Лейаут списка

Отдельная карточка на каждый элемент, вертикально. Элемент содержит:

- **Grab-ручка слева** для drag-and-drop (иконка `::` или `↕`). Перетаскивание мышью меняет `sortOrder`.
- **Заголовок = question**. Жирный, 16pt.
- Бейджи справа от заголовка:
  - `Опубликовано` (зелёный) / `Черновик` (серый) — по `isPublished`.
  - Категория (синий, текстом) — если `category !== null`. При пустом — бейджа нет.
- **Превью ответа**: одна-две строки, обрезанные с `…` — чтобы список был компактным.
- Кнопки в правом верхнем углу элемента:
  - **«Редактировать»** (иконка карандаша) — открывает модалку.
  - **«Удалить»** (иконка корзины) — открывает confirm-диалог.
- При клике на заголовок / тело — разворачивается вниз полный **отрендеренный Markdown** ответа (аккордеон) — чтобы владелец сразу видел, как это увидит клиент.

Когда список пустой — рисуй empty-state с иллюстрацией и текстом:

> В FAQ пока нет вопросов. Добавьте первый, чтобы он появился на лендинге сети.

Кнопка под текстом: **«+ Добавить вопрос»**.

### Модалка добавления / редактирования

Полноэкранная modal или большой drawer — так удобнее редактировать длинный Markdown.

Поля:

1. **Вопрос** (`question`). Single-line input, max 500, счётчик символов внизу справа.
2. **Ответ** (`answer`). Markdown-textarea. Обязательно должен иметь:
   - Панель форматирования сверху: `B` / `I` / list / link / inline code / H3 (минимум).
   - **Preview-режим** в переключателе «Редактор / Превью» либо split-view (слева редактор, справа превью). Рендер Markdown — используй `react-markdown` с GFM + `remark-gfm`, и обязательно санитайзер (`rehype-sanitize` дефолтной схемой; только inline-формат, без raw HTML).
   - max 10000 символов, счётчик. При приближении к лимиту — оранжевый. При превышении — красный и блокируем «Сохранить».
3. **Категория** (`category`). Text input с автокомплитом из уже существующих `category` всех элементов организации (чтобы владелец не плодил вариации «Оплата» / «оплата» / «Оплата "). Max 64, опционально, пусто → `null`.
4. **Опубликовано** (`isPublished`). Toggle. Подпись рядом:
   - Включён → «Виден на публичном лендинге» (зелёная плашка).
   - Выключен → «Черновик — виден только в админке» (серая плашка).

Кнопки модалки:

- **«Сохранить»** (primary) → `POST` или `PATCH`. По успеху — тост «Сохранено» и закрыть модалку.
- **«Отменить»** → закрыть без сохранения. Если были несохранённые изменения — confirm-диалог «Отменить изменения?».

### Drag-and-drop

- Используй `@dnd-kit/core` + `@dnd-kit/sortable` (или аналогичную проверенную библиотеку; НЕ `react-beautiful-dnd`, он deprecated).
- При отпускании элемента:
  - Оптимистично обновляем локальный порядок.
  - Считаем новый массив `{ id, sortOrder }` с шагом 10 (10, 20, 30…).
  - Шлём `PATCH /admin/faq/reorder`.
  - Если сервер вернул ошибку — откат к предыдущему порядку и тост об ошибке.
  - Если вернул 200 — перезаписываем локальный стейт тем, что пришло от сервера (source of truth).

### Удаление

- Confirm-модалка: заголовок «Удалить вопрос?», тело «Это действие нельзя отменить. Вопрос «{question}» исчезнет с лендинга.»
- Кнопки: **«Удалить»** (destructive, красная) и **«Отмена»**.

### Ошибки

Бэкенд возвращает:

- **400 Bad Request** — валидация (например, `question` пустой, `answer` пустой, `category` длиннее 64). Показывай `response.message` (если массив — первое значение) inline рядом с полем или тостом.
- **403 Forbidden** — роль не разрешена. Не должно случаться, если навигация правильно скрыта, но на всякий случай показывай «Недостаточно прав».
- **404 Not Found** — элемент не найден (устарел стейт, кто-то удалил в параллельной вкладке). Покажи тост «Элемент уже удалён» и перезагрузи список.

## Поведение стейта

- При открытии раздела — `GET /admin/faq`. Если 403 — редирект назад с тостом.
- Список хранить локально (React Query / SWR). Инвалидация кэша после любого `POST`/`PATCH`/`DELETE`/`reorder` либо мерж ответа сервера.
- При первой загрузке пустого списка показать empty-state (см. выше).
- Персистентных настроек в localStorage для этого раздела не нужно.

## Доступность и UX мелочи

- Все кнопки-иконки должны иметь `aria-label`.
- Drag-handle должен поддерживать keyboard drag (пробел / стрелки) — поставщик `@dnd-kit` это даёт из коробки.
- Markdown-превью в списке должен корректно отображать русские буквы, длинные ссылки переносить (`overflow-wrap: anywhere`).
- Отображай локализованные даты `createdAt`/`updatedAt` в подвале элемента мелким серым шрифтом — полезно для владельца сети, когда он пытается вспомнить, когда редактировал.
