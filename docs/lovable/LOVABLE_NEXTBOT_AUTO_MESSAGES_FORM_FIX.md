# Исправление формы «Новый шаблон автосообщения» — промпт для Lovable

**Задача:** переработать только модальное окно создания/редактирования шаблона автосообщения Nextbot.  
**Не трогать:** webhook settings, тестовую отправку, журнал логов, список шаблонов (кроме отображения тайминга в карточке).  
**API бэкенда не менять** — исправления только на фронте.

Справка: `LOVABLE_NEXTBOT_AUTO_MESSAGES.md`, исходный промпт `LOVABLE_NEXTBOT_AUTO_MESSAGES_PROMPT.md`.

---

## Что сейчас неправильно (обязательно исправить)

1. **Одна и та же форма** для всех типов сценария: везде «смещение 1 час», «до/после», «категория» — пользователь создаёт шаблоны с неверным временем отправки.
2. **Дефолт «1 час»** неверен для холда (нужно 5 мин), follow-up (24 **дня**), feedback (15 **минут**), подтверждения (сразу, без смещения).
3. **Категория** показывается там, где не нужна (подтверждение, напоминание, холд).
4. **Категория не выбрана** для follow-up/feedback — сохранение падает с 400 (`serviceCategoryId` обязателен).
5. **Радио «после визита»** для напоминания и «после истечения брони» для холда — вводят в заблуждение; по продукту нужны только корректные направления (см. таблицу ниже).
6. **Один плейсхолдер текста** («Напоминаем о записи…») на всех типах — при смене сценария подставлять **разный пример текста**.
7. **Не используется** `GET .../presets` при смене типа сценария.

---

## Общие правила формы

- При открытии модалки **создания**: загрузить `GET /studios/:studioId/nextbot-auto-messages/presets` и `GET .../variables`.
- При смене **«Тип сценария»** (`triggerType`):
  - найти в массиве presets **все** записи с этим `triggerType`;
  - если пресетов несколько (напоминание) — показать подтип или кнопки быстрого выбора (см. ниже);
  - подставить в скрытое состояние формы: `anchor`, `direction`, `offsetValue`, `offsetUnit`, `minLeadDays`;
  - показать `hint` из пресета серым текстом под таймингом;
  - обновить placeholder/пример `messageText` (см. раздел «Примеры текста»).
- Поля `anchor`, `direction` **не показывать пользователю** как enum — только человекочитаемые подписи; в API уходят технические значения из пресета.
- **Не отправлять** `serviceCategoryId` в body, если поле скрыто (omit, не `null` строкой).
- Валидация перед POST/PATCH:
  - `messageText` не пустой;
  - для `FOLLOWUP_AFTER_VISIT` и `FEEDBACK_REQUEST` — выбрана категория;
  - `offsetValue` ≥ 1.

---

## Видимость полей по типу сценария

| Тип (`triggerType`) | Подпись в UI | Показать пользователю | Скрыть / не отправлять |
|---------------------|--------------|------------------------|-------------------------|
| `BOOKING_CONFIRMED` | Подтверждение записи | Текст, «Активен» | Смещение, до/после, minLeadDays, **категория** |
| `REMINDER_BEFORE_VISIT` | Напоминание о визите | Смещение (число + единица), minLeadDays (опционально), текст, активен | Категория, «после визита» |
| `HOLD_EXPIRY_WARNING` | Истечение брони | Только текст + активен + **readonly** подпись тайминга | Смещение (редактируемое), категория, до/после |
| `FOLLOWUP_AFTER_VISIT` | Follow-up после визита | Смещение в **днях**, **категория*** , текст, активен | «До визита», minLeadDays |
| `FEEDBACK_REQUEST` | Запрос оценки | Смещение в **минутах**, **категория*** , текст, активен | «До визита», minLeadDays |

\* Категория обязательна, красная звёздочка, подпись: «Для follow-up и запроса оценки категория обязательна».

## Значения API при сохранении (жёстко из пресетов)

### Подтверждение записи

```json
{
  "triggerType": "BOOKING_CONFIRMED",
  "anchor": "NONE",
  "direction": "AFTER",
  "offsetValue": 0,
  "offsetUnit": "MINUTES"
}
```

Под полем типа: *«Отправляется сразу при статусе „Забронировано“. Время и категория не настраиваются.»*

### Напоминание — два пресета (два отдельных шаблона в CRM)

Не один шаблон «на все случаи», а **два типовых варианта** в UI:

**Вариант A — за сутки** (пресет из API):

```json
{
  "triggerType": "REMINDER_BEFORE_VISIT",
  "anchor": "APPOINTMENT_START",
  "direction": "BEFORE",
  "offsetValue": 1,
  "offsetUnit": "DAYS",
  "minLeadDays": 2
}
```

Подсказка: *«Только если с момента брони до визита прошло не меньше 2 суток.»*

**Вариант B — за 4 часа**:

```json
{
  "triggerType": "REMINDER_BEFORE_VISIT",
  "anchor": "APPOINTMENT_START",
  "direction": "BEFORE",
  "offsetValue": 4,
  "offsetUnit": "HOURS"
}
```

`minLeadDays` не передавать.

**UI для напоминания:** при выборе «Напоминание о визите» показать segmented control или select:

- «За сутки (если бронь ≥ 2 дней до визита)» → вариант A  
- «За 4 часа» → вариант B  
- «Своё смещение» (опционально, для продвинутых) → поля число + единица (MINUTES/HOURS/DAYS), только `direction: BEFORE`, `anchor: APPOINTMENT_START`, поле minLeadDays опционально.

Единица по умолчанию для «своё»: HOURS. **Не показывать** radio «После начала визита».

### Истечение брони (холд)

Тайминг **только для чтения**:

*«За 5 минут до окончания ночной предброни (статус „Предварительная“).»*

В API всегда:

```json
{
  "triggerType": "HOLD_EXPIRY_WARNING",
  "anchor": "HOLD_EXPIRES_AT",
  "direction": "BEFORE",
  "offsetValue": 5,
  "offsetUnit": "MINUTES"
}
```

### Follow-up после визита

```json
{
  "triggerType": "FOLLOWUP_AFTER_VISIT",
  "anchor": "VISIT_DONE_AT",
  "direction": "AFTER",
  "offsetValue": 24,
  "offsetUnit": "DAYS"
}
```

UI: одно поле «Через N **дней** после завершения визита» (число, default 24). Внутри маппить на `offsetValue` + `offsetUnit: "DAYS"`. Категория — select обязательный.

### Запрос оценки

```json
{
  "triggerType": "FEEDBACK_REQUEST",
  "anchor": "VISIT_DONE_AT",
  "direction": "AFTER",
  "offsetValue": 15,
  "offsetUnit": "MINUTES"
}
```

UI: «Через N **минут** после завершения визита» (default 15). Категория обязательна.

## Примеры текста (`messageText`) при смене типа

Подставлять в textarea только если поле пустое или пользователь не редактировал (флаг `messageTextTouched`).

| Тип | Пример |
|-----|--------|
| Подтверждение | `{{name}}, ваша запись подтверждена: {{service}}, {{appointmentDate}} в {{appointmentTime}}, мастер {{master}}, {{studio}}.` |
| Напоминание | `Здравствуйте, {{name}}! Напоминаем о записи на {{service}} {{appointmentDate}} в {{appointmentTime}}.` |
| Холд | `{{name}}, ваша предварительная бронь скоро истечёт. Успейте оплатить, чтобы сохранить время: {{appointmentDate}} {{appointmentTime}}.` |
| Follow-up | `{{name}}, давно не были у нас! Запишитесь снова на {{category}} — будем рады видеть вас в {{studio}}.` |
| Оценка | `{{name}}, как прошёл визит? Оцените от 1 до 5. Ваш ответ поможет нам стать лучше.` |

Переменные — кнопки из `GET .../variables` (без изменений).

## Редактирование существующего шаблона

`GET /studios/:studioId/nextbot-auto-messages/:templateId` → заполнить форму.

- Определить подтип напоминания по `offsetValue` + `offsetUnit` + `minLeadDays` (1 DAY + minLeadDays 2 → «за сутки», 4 HOURS → «за 4 часа», иначе «своё»).
- Для холда показывать readonly тайминг, даже если в БД старые неверные значения; при сохранении **перезаписать** корректным пресетом 5 MINUTES (миграция «исправить при сохранении»).
- Для `BOOKING_CONFIRMED` при сохранении всегда слать пресет подтверждения (0 MINUTES, NONE).

## Список шаблонов — мелкое улучшение

В карточке шаблона показывать **человекочитаемый** тайминг, не сырой enum:

| triggerType | Формат строки |
|-------------|----------------|
| BOOKING_CONFIRMED | «Сразу при бронировании» |
| REMINDER_BEFORE_VISIT | «За N … до визита» + при `minLeadDays` — «(если бронь ≥ N дн.)» |
| HOLD_EXPIRY_WARNING | «За 5 мин до конца холда» |
| FOLLOWUP_AFTER_VISIT | «Через N дн. после визита · {категория}» |
| FEEDBACK_REQUEST | «Через N мин после визита · {категория}» |

## Баннер-подсказка в модалке напоминаний

Если в филиале ещё нет второго шаблона напоминания (проверка по списку GET шаблонов):

- есть только «за сутки» → *«Рекомендуем добавить второй шаблон: напоминание за 4 часа.»*
- есть только «за 4 часа» → *«Рекомендуем добавить шаблон: напоминание за сутки (с условием ≥ 2 дней с брони).»*

## Чеклист приёмки (только форма)

- [ ] Подтверждение: нет полей смещения и категории; в API уходит пресет BOOKING.
- [ ] Напоминание: нет «после визита»; есть выбор «за сутки» / «за 4 часа»; minLeadDays только у «за сутки» (= 2).
- [ ] Холд: тайминг readonly 5 мин; категории нет.
- [ ] Follow-up: дни + обязательная категория; default 24 дня.
- [ ] Оценка: минуты + обязательная категория; default 15 мин.
- [ ] Смена типа подставляет пресет и меняет пример текста.
- [ ] Сохранение follow-up без категории блокируется на клиенте с понятной ошибкой.
- [ ] Редактирование старого «плохого» шаблона холда при сохранении исправляет offset на 5 MINUTES.

## API (без изменений)

| Действие | Метод |
|----------|--------|
| Пресеты | `GET /studios/:studioId/nextbot-auto-messages/presets` |
| Переменные | `GET .../variables` |
| Категории | `GET /services/categories?studioId=...` (`isOfferedInStudio === true`) |
| Создать | `POST /studios/:studioId/nextbot-auto-messages` |
| Изменить | `PATCH /studios/:studioId/nextbot-auto-messages/:templateId` |

Тело POST/PATCH — как в `CreateNextbotAutoMessageTemplateDto` на бэкенде:  
`triggerType`, `anchor`, `direction`, `offsetValue`, `offsetUnit`, `messageText`, `isActive`, опционально `minLeadDays`, `serviceCategoryId`.
