# Промпт для Lovable: автор записи и «Только мои»

Скопируйте блок ниже в Lovable как задачу на фронтенд.

---

## Промпт (copy-paste)

```
Реализуй на фронтенде отображение автора записи (кто создал бронь) и фильтр «Только мои записи» для менеджера/администратора. Бэкенд уже готов — менять API не нужно.

### Контекст

- «Автор» — это НЕ мастер на приёме (`staff`), а кто завёл запись в системе: менеджер, админ, Nextbot, лендинг.
- При создании записи в CRM бэкенд сам ставит `createdByUserId` = текущий пользователь.
- Старые записи без автора: `author = "CRM"`.

### API

Base: `https://aidaproject-production.up.railway.app` (или ваш `VITE_API_URL`).
Заголовок: `Authorization: Bearer <accessToken>`.

**Список записей филиала:**
`GET /studios/:studioId/appointments`

Query (опционально):
- `date=YYYY-MM-DD` — записи за один день (как в журнале по дате).
- `onlyMine=true` или `onlyMine=1` — только записи, созданные текущим пользователем (`createdByUserId` = я).
- `createdByUserId=<userId>` — явный фильтр по автору (для отладки/админки).
- `staffUserId=<userId>` — только записи к указанному мастеру (исполнитель визита). Комбинируется с фильтрами автора.

В каждом объекте записи в ответе есть:
- `author` — строка для UI, например `Айгуль Смагулова (Администратор)`, `Nextbot`, `Лендинг`, `CRM`
- `createdSource`: `CRM` | `NEXTBOT` | `LANDING`
- `createdByUserId`: string | null
- `createdByUser`: { id, role, email, staffProfile: { firstName, lastName } } | null

Не вычисляй подпись автора на фронте — показывай поле `author`.

### Задача 1 — Журнал записей мастеров (календарь / список на день)

Файлы/экраны: журнал записей (`LOVABLE_APPOINTMENT_LOG.md`), таблица или карточки записей.

1. Добавь колонку или строку **«Автор»** в списке записей и в детальной карточке/модалке записи.
2. Значение: `appointment.author` (fallback `—` только если поля нет в ответе).
3. Визуально отличай каналы без сотрудника: `Nextbot`, `Лендинг`, `CRM` — нейтральный бейдж/серый текст; сотрудник CRM — обычный текст.
4. После `POST` создания записи в CRM обновляй список — в ответе создания тоже есть `author`.

### Задача 2 — Блок «Мои записи за месяц» (для MANAGER / ADMIN)

Экран: дэшборд менеджера или отдельная вкладка «Мои записи» (если дэшборд владельца недоступен роли — см. `LOVABLE_DASHBOARD_ACCESS_RESTRICTION.md`; этот блок только для MANAGER и ADMIN своего филиала).

**Полная спецификация фильтров:** `LOVABLE_ADMIN_MY_APPOINTMENTS_FILTERS_PROMPT.md`.

1. Селектор месяца (по умолчанию текущий календарный месяц в таймзоне студии — как в остальном приложении).
2. **Панель фильтров** над таблицей:
   - Toggle **«Только мои»** → `onlyMine=true` (по умолчанию включён).
   - Select **«Мастер»** → `staffUserId` (мастера из `GET .../staff`, role MASTER; первая опция «Все мастера»).
   - Select **«Создал»** → `createdByUserId` (ADMIN/MANAGER из staff; показывать только когда «Только мои» выключен).
3. Загрузка данных:
   - Запрос: `GET /studios/:studioId/appointments?<filters>` **без** `date`.
   - На клиенте отфильтруй массив: `startAt` попадает в выбранный месяц `[monthStart, monthEnd)` в UTC/таймзоне студии — той же логикой, что и другие фильтры по датам в проекте.
   - Альтернатива (если уже есть цикл по дням месяца): к каждому `?date=YYYY-MM-DD` добавляй те же query-параметры.
4. Таблица: дата/время, клиент, мастер (`staff`), услуга, статус, **автор** (`author`), сумма визита для строки.
   - Сумма строки: как в карточке клиента / завершении визита — `completedMoneyPaid` если статус DONE, иначе `prepaymentAmount` или `service.defaultPrice` (используй ту же формулу, что уже есть в приложении для денег по записи).
5. Над таблицей — итог **«Итого за месяц»**: сумма по отфильтрованным строкам (пересчитывать при смене месяца и при переключении фильтра).
6. Состояние фильтров — в URL query (`onlyMine=1`, `staffUserId=`, `createdByUserId=`, `month=`) или localStorage.
7. Роли: переключатель и блок «Мои записи» показывать для `MANAGER` и `ADMIN`. Для `MASTER` не показывать «только мои по автору» (у мастера свой фильтр — только свои приёмы). Для `OWNER` / `DEPUTY_OWNER` — опционально показать фильтр по автору через общий список без `onlyMine` или отдельный select сотрудников (`createdByUserId`).

### Задача 3 — Дэшборд владельца (если на экране уже есть список записей)

Если на `GET /studios/:studioId/dashboard` или на UI дэшборда выводится список записей за период:
- добавь колонку **Автор** (`author`);
- не ломай существующие метрики `overview.revenue` — они с бэкенда;
- фильтр «Только мои» на дэшборде владельца не обязателен (роль OWNER видит всё); для менеджера используй Задачу 2.

### UX

- Подсказка (tooltip) у «Автор»: «Кто создал запись в CRM или через бота/лендинг».
- Пустой автор не ожидается — всегда есть `author`.
- Ошибки 401 → логин; 403 → toast «Нет доступа».

### Чеклист приёмки

- [ ] В журнале записей на день видна колонка «Автор».
- [ ] В карточке записи отображается `author`.
- [ ] У менеджера есть переключатель «Только мои»; при включении запрос с `onlyMine=true`.
- [ ] Select «Мастер» передаёт `staffUserId`; select «Создал» — `createdByUserId` (когда «Только мои» выкл.).
- [ ] За выбранный месяц показываются только «мои» созданные записи и корректная сумма итого.
- [ ] При выключении «Только мои» — полный список филиала за тот же месяц и другая сумма итого.
- [ ] Nextbot/лендинг отображаются как `author`, без подстановки имени менеджера.

### Не делать

- Не дублировать логику автора на фронте.
- Не путать `staff` (мастер на приёме) с `author` (кто создал бронь).
- Не менять бэкенд и Prisma.

Сверься с `docs/lovable/LOVABLE_APPOINTMENT_AUTHOR.md` и `LOVABLE_APPOINTMENT_LOG.md`.
```

## Краткая справка для разработчика

| Вопрос | Ответ |
|--------|--------|
| Что показывать в UI? | `appointment.author` |
| Как фильтровать «мои»? | `?onlyMine=true` |
| Как фильтровать по мастеру? | `?staffUserId=<userId>` |
| Комбо? | `?onlyMine=true&staffUserId=...` |
| За месяц? | Клиентский фильтр по `startAt` после загрузки, или `date` по дням + query-фильтры |
| Кто видит кнопку? | MANAGER, ADMIN (основной сценарий) |
| Полный промпт UI | `LOVABLE_ADMIN_MY_APPOINTMENTS_FILTERS_PROMPT.md` |
