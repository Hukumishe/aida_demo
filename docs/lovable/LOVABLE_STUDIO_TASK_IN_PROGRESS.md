# Задачи филиала: «В работе» и кто завершил

## Бэкенд (готово)

### Статусы

| `status`       | Базовая подпись | `statusLabel` в API (примеры)        |
|----------------|-----------------|--------------------------------------|
| `OPEN`         | Открыта         | `Открыта`                            |
| `IN_PROGRESS`  | В работе        | `В работе (Иван Иванов)`             |
| `DONE`         | Выполнена       | `Выполнена (Мария Петрова)`          |
| `CANCELLED`    | Отменена        | `Отменена`                           |

Справочник: **`GET /task-statuses`** → `[{ value, label }]`.

В каждой задаче в списке/деталях дополнительно:

- **`statusLabel`** — строка для UI (с именем исполнителя для `IN_PROGRESS` и `DONE`).
- **`inProgressBy`** — пользователь, нажавший «Взять в работу» (`null`, если не в работе).
- **`completedBy`** — пользователь, переведший в `DONE` (`null`, пока не выполнена).

### Взять в работу

```http
POST /studios/:studioId/tasks/:taskId/take-in-progress
Authorization: Bearer …
```

- Только из **`OPEN`**.
- **Мастер** — только свои задачи (`assigneeUserId` = он).
- **Менеджер / админ филиала** — свои и из общего пула (как у `PATCH`).
- **Владелец / зам / developer** — любая задача организации.

Не использовать `PATCH` со `status: IN_PROGRESS` для мастера — вернётся 400 с подсказкой на этот POST.

### Завершить

`PATCH` со `status: "DONE"` (как раньше). Бэкенд сам проставляет **`completedByUserId`** текущим пользователем; в ответе **`statusLabel`** = «Выполнена (Имя)».

### UI (Lovable)

1. Кнопка **«Взять в работу»** на карточке/в списке при `status === 'OPEN'` → POST `take-in-progress`, обновить карточку из ответа (`statusLabel`, `inProgressBy`).
2. Показывать **`statusLabel`** вместо сырого enum там, где нужен человекочитаемый статус.
3. В выполненных — **`statusLabel`** или блок «Завершил:» из **`completedBy.staffProfile`**.
4. Фильтры/вкладки: учесть `IN_PROGRESS` между «Открытые» и «Выполненные».
