# Промпт для Lovable: экран роли DEVELOPER (платформа / организации)

Скопируйте блок **«Промпт»** ниже целиком в чат Lovable.

---

## Промпт

Добавь в приложение **отдельный раздел только для роли `DEVELOPER`** — экран **«Организации»** (платформенное управление тенантами). Остальные роли (`OWNER`, `ADMIN`, …) **не должны** видеть этот пункт меню и маршрут; при прямом заходе на URL — редирект на дашборд или 403.

### Авторизация

- После `**POST /auth/login`** используй `**Authorization: Bearer <accessToken>**` для всех запросов.
- Роль бери из `**GET /auth/me` → `user.role**`. Экран показывай **только если** `user.role === 'DEVELOPER'`.

### API бэкенда (NestJS AIDA)

Все пути относительно базового URL API (например `VITE_API_URL`).


| Действие                               | Метод и путь                         | Тело / примечание                                                                                                                                                                                                                                          |
| -------------------------------------- | ------------------------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Список всех организаций                | `GET /organizations`                 | **Только DEVELOPER.** Иначе 403.                                                                                                                                                                                                                           |
| Одна организация                       | `GET /organizations/:organizationId` | Детальная карточка (имя, slug, id, даты и т.д. — как вернёт API).                                                                                                                                                                                          |
| Создать организацию                    | `POST /organizations`                | `{ "name": string, "slug?": string }`. Поле `slug` опционально: латиница, цифры, дефис.                                                                                                                                                                    |
| Список всех филиалов                   | `GET /studios`                       | Для **DEVELOPER** бэкенд возвращает **все** студии **всех** организаций. Используй для таблицы «филиалы» с колонкой **organizationId** (или вложенным полем организации, если есть в ответе).                                                              |
| Создать филиал в выбранной организации | `POST /studios`                      | Тело: `{ "name": string, "address?": string, "timezone?": string, "organizationId": string }`. Поле `**organizationId` обязательно для сценария DEVELOPER**, когда создаёшь филиал **не в «своей» орг пользователя**, а в выбранной из списка организаций. |
| Изменить название / адрес филиала      | `PATCH /studios/:studioId`           | `{ "name"?: string, "address"?: string \| null }`. **OWNER, DEPUTY_OWNER, DEVELOPER.** |
| Удалить филиал                         | `DELETE /studios/:studioId`          | **Только DEVELOPER.** 400, если к филиалу привязаны сотрудники. |


**Важно:** для `POST /studios` бэкенд для роли DEVELOPER берёт `organizationId` из тела, если оно непустое; иначе — из профиля пользователя. На экране платформы всегда передавай `**organizationId`** явно при создании филиала из карточки организации.

### UX экрана (минимально полезный набор)

1. **Заголовок:** например «Организации» или «Платформа».
2. **Таблица или карточки** — данные из `**GET /organizations`** (сортировка по умолчанию с бэка: новые сверху).
3. Кнопка **«Создать организацию»** → модальное окно с полями **Название** (обязательно), **Slug** (опционально), сабмит на `**POST /organizations`**. После успеха — обновить список и показать toast.
4. Строка организации: показать **id** (можно моноширинным, с кнопкой копирования), **name**, **slug** при наличии. Действие **«Открыть»** или раскрытие блока.
5. Внутри выбранной организации — **список филиалов**, отфильтрованный из `**GET /studios`** по `organizationId === выбранная организация` (клиентская фильтрация допустима).
6. Кнопка **«Добавить филиал»** для этой организации → форма с `name`, опционально `address`, `timezone`; в теле `**POST /studios`** всегда передавай `**organizationId**` текущей организации.
7. Обработка ошибок: **403** на `GET /organizations` — не показывать экран (пользователь не DEVELOPER). **400** от валидации slug — показать текст с бэка.

### Навигация

- Пункт сайдбара / таба: **«Организации»** (или «Платформа»), видимый **только при `role === 'DEVELOPER'`**.
- Не дублируй этот экран для `OWNER` — у владельца свои сценарии внутри одной сети (`LOVABLE_ORGANIZATION_INTEGRATION_PROMPT.md`).

### Стили

Соблюдай визуальный стиль текущего приложения Lovable (типографика, отступы, кнопки, тёмная/светлая тема как в проекте).
