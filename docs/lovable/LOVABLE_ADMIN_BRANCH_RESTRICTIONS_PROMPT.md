# Единый промпт для Lovable: админ филиала, завершение визита, услуги по мастеру

Скопируйте блок **«Задача»** целиком в чат Lovable. Бэкенд (NestJS + Prisma, aida_demo) уже реализован.

---

## Контекст

- CRM: `Authorization: Bearer <JWT>`, роль пользователя в JWT (`ADMIN`, `MASTER`, `MANAGER`, `OWNER`, …).
- Филиал админа: `user.studioId` из профиля / JWT.
- Не ломать существующие экраны для OWNER / MANAGER / MASTER — изменения точечные по роли.

---

## Задача

Реализуй на фронте четыре связанных изменения.

### 1. Модалка «Завершить визит» (все роли с доступом к записи)

В модальном окне **«Детали записи»** кнопка **«Завершить»** видна при статусах `BOOKED` или `ARRIVED`, скрыта при `DONE` / `CANCELLED`.

По нажатию — **форма оплаты** (не отправлять done без подтверждения):

| Поле | UI | API |
|------|-----|-----|
| Сумма оплаты | number, ₸ | `completedMoneyPaid` |
| Списание кэшбека | number, бонусы | `bonusesUsed` |
| Тип оплаты | select | `paymentMethod` |

Значения `paymentMethod`:
- `CASH` — Наличные
- `BANK_TRANSFER` — Перевод
- `KASPI_PAY` — Kaspi Pay

**Запрос:** `POST /appointments/:id/done`

```json
{
  "completedMoneyPaid": 8500,
  "bonusesUsed": 500,
  "paymentMethod": "CASH"
}
```

Правила:
- Поля в UI сделать **обязательными** (на бэкенде опциональны; если `completedMoneyPaid` не передать — считается `стоимость визита − bonusesUsed`).
- После успеха обновить запись в календаре/списке; показать в деталях `completedMoneyPaid`, `completedBonusesUsed`, `completedPaymentMethod` если приходят в ответе.
- Ошибки: `400` (уже done/cancelled, невалидная сумма), `403`, `404` — toast с текстом с бэкенда.

---

### 2. Роль ADMIN: не редактировать мастеров

Для `user.role === 'ADMIN'`:

**Скрыть в UI** (не полагаться только на 403):
- Редактирование карточки мастера (`PATCH /staff/:userId`, профиль, услуги, override, увольнение/восстановление).
- Кнопки: «Редактировать», «Сохранить», «Добавить услугу», «Удалить услугу», override, «Уволить» — на пользователях с ролью `MASTER`.

**Оставить:**
- `GET /studios/:studioId/staff` — список мастеров (просмотр).
- Просмотр карточки мастера read-only.

Бэкенд на изменения мастера от ADMIN вернёт **403** с текстом вроде «Администратор не может редактировать мастеров».

---

### 3. Роль ADMIN: нет общего списка клиентов

Для `user.role === 'ADMIN'`:

**Не вызывать и не показывать:**
- `GET /clients` (список, поиск, пагинация)
- `GET /clients/segments`
- `GET /clients/referred`
- Пункты меню / вкладки: «Клиенты», сегменты на дашборде, реферальный список.

**Разрешено:**
- `GET /clients/:id` — открытие карточки клиента **только из записи** (клик по имени клиента в модалке/строке appointment).

Навигация: у ADMIN нет входа в общий каталог клиентов; путь ` /clients` или аналог — редирект на календарь/записи или 403 не показывать (просто скрыть пункт).

Бэкенд на список для ADMIN: **403** — «Администратору филиала недоступен общий список клиентов…».

---

### 4. Создание записи: услуги только выбранного мастера (все роли)

Сейчас при создании записи показывается **весь каталог** — исправить для **всех ролей**.

**Порядок в форме:**
1. Выбор филиала (если есть).
2. Выбор **мастера** (`staffUserId`).
3. Только после мастера — загрузка и выбор **услуг**.

**API (один из вариантов):**

**Вариант A (рекомендуется):**
```
GET /services?studioId={studioId}&staffUserId={staffUserId}
```
Возвращает только услуги, привязанные к мастеру в филиале и доступные в студии.

**Вариант B:**
```
GET /staff/{staffUserId}/services
```

При смене мастера — **сбросить** выбранные услуги и перезапросить список.

При `POST /studios/:studioId/appointments` бэкенд вернёт **400** «Услуга недоступна для выбранного мастера», если услуга не в `staff_services` — не показывать такие услуги в UI.

Не запрашивать полный `GET /services` без `staffUserId` на шаге выбора услуг в форме записи.

## Чеклист приёмки

- [ ] Done: модалка с суммой, бонусами, типом оплаты → `POST .../done`
- [ ] ADMIN: мастера только просмотр, без edit-кнопок
- [ ] ADMIN: нет меню/экрана списка клиентов; карточка клиента из записи
- [ ] Форма записи: услуги после мастера, `staffUserId` + `studioId` в query
- [ ] OWNER/MANAGER/MASTER: поведение без регрессий

---

## Ограничения

- Не менять контракты других фич (waitlist, nextbot, лендинг).
- Использовать существующий API-клиент и обработку JWT/ролей проекта.
- Типы TypeScript для `paymentMethod`: `'CASH' | 'BANK_TRANSFER' | 'KASPI_PAY'`.
