# Промпт для Lovable: личный дневник мастера о клиенте

Скопируйте блок **«Промпт»** ниже в чат Lovable.

Backend AIDA уже реализован: отдельные заметки мастера, не путать с `Client.notes` и `Appointment.comment`.

---

## Промпт

### Задача

Добавь **личный дневник мастера** о клиенте с быстрым доступом **до / во время / после** визита.

Правила доступа:

| Роль | Что видит |
|------|-----------|
| **MASTER** | только **свои** заметки |
| **OWNER / DEPUTY_OWNER** | **все** заметки всех мастеров |
| **ADMIN / MANAGER / SERVICE** | **нет доступа** |

Не смешивать с:

- **Комментарий к записи** (`appointment.comment`) — операционная заметка CRM
- **Заметки клиента** (`client.notes`) — общее поле CRM

---

### 1. Мастер: быстрый доступ из журнала записей

#### A) Блок в модалке «Детали записи» (`AppointmentDetailsModal`)

Добавь секцию **«Мой дневник»** (под клиентом / услугой, над кнопками статуса):

**Загрузка:**

`GET /appointments/:appointmentId/staff-diary`

Ответ:

```json
{
  "items": [
    {
      "id": "csd_...",
      "clientId": "cli_...",
      "staffUserId": "usr_...",
      "appointmentId": "apt_...",
      "body": "Аллергия на ...",
      "createdAt": "2026-06-20T10:00:00.000Z",
      "updatedAt": "2026-06-20T10:00:00.000Z"
    }
  ],
  "myNotesCount": 3
}
```

- `items` — заметки **мастера по этому клиенту** (не только по текущей записи), новые сверху.
- `myNotesCount` — для badge «есть заметки» (если > 0).

**Добавление заметки:**

`POST /appointments/:appointmentId/staff-diary`

```json
{ "body": "Текст заметки" }
```

Сервер сам подставляет `clientId`, `appointmentId`, `staffUserId`.

**Редактирование / удаление своей заметки:**

- `PATCH /staff-diary/:id` — `{ "body": "..." }`
- `DELETE /staff-diary/:id`

UI:

- textarea + кнопка «Сохранить» (Enter отправляет, Shift+Enter — новая строка);
- список последних замetок с датой;
- у каждой своей заметки — «Изменить» / «Удалить»;
- loading / toast на ошибках API.

#### B) Быстрый доступ из строки журнала (без полной модалки)

На строке записи в журнале мастера:

- иконка **📝** или «Дневник»;
- если `myNotesCount > 0` (или после первого GET) — маленькая метка;
- tap → **bottom sheet**: textarea + последние 2–3 заметки + «Сохранить».

Используй тот же `GET/POST .../staff-diary`.

#### C) Мягкий nudge после действий (не блокирующий)

После «Клиент пришёл» или «Завершить» покажи snackbar:

> «Добавить заметку в дневник?» → открывает bottom sheet.

Не заставляй заполнять каждый раз.

---

### 2. Owner / Deputy: вкладка в карточке клиента

На экране клиента добавь вкладку **«Заметки мастеров»**:

`GET /clients/:clientId/staff-diary`

Ответ:

```json
{
  "items": [
    {
      "id": "csd_...",
      "clientId": "cli_...",
      "staffUserId": "usr_...",
      "appointmentId": "apt_...",
      "body": "...",
      "createdAt": "...",
      "updatedAt": "...",
      "author": {
        "staffUserId": "usr_...",
        "name": "Иван Петров"
      }
    }
  ]
}
```

UI: лента с **именем мастера**, датой, текстом. Только чтение (owner не редактирует чужой дневник).

---

### 3. Права и ошибки

- Все запросы с `Authorization: Bearer`.
- Если роль не имеет доступа — не показывай блок.
- MASTER не использует `GET /clients/:id` для дневника — только appointment-эндпоинты.

---

### 4. Стили

- Сохрани тёмную тему и стиль текущей CRM.
- Секция компактная: мастер должен успеть записать мысль за 5–10 секунд.
- Не дублируй поле «Комментарий к записи».

---

### 5. Тест-кейсы

1. MASTER открывает запись → видит только свои заметки по клиенту.
2. MASTER добавляет заметку из модалки и из bottom sheet.
3. Другой MASTER не видит чужие заметки.
4. OWNER в карточке клиента видит все заметки с автором.
5. ADMIN/MANAGER не видят блок дневника.
