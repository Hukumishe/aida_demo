# Рабочие часы отдела маркетинга — промпт для Lovable (вкладка «Маркетинг»)

> ВАЖНО: это часы **отдела маркетинга** (менеджеров, которые выставляют счета Kaspi через Nextbot), а **не** часы работы самого салона и не расписание мастеров. Не путать с графиком студии или сменами персонала.

---

## Обзор

Во вкладке **«Маркетинг»** (там же, где уже настраивается акция «Приведи подругу» и лимит оплаты бонусами) нужно добавить блок **«Рабочие часы отдела маркетинга»**.

Эти часы используются Nextbot (ИИ-агентом) для маршрутизации оплаты после предварительной брони:

- **Внутри интервала [начало, конец)** — «день»: бэкенд ставит задачу живому маркетинг-менеджеру выставить счёт Kaspi.
- **Вне интервала** — «ночь»: клиенту сразу отдаются статичные реквизиты Kaspi (телефон + ФИО держателя), включается **30-минутный таймер удержания** предварительной брони. Если за 30 минут клиент не прислал чек и менеджер не подтвердил оплату — слот автоматически освобождается.

Если часы **не заданы** (оба null) — считается, что отдел маркетинга работает круглосуточно и ночной путь **отключён** (всегда идёт задача менеджеру).

Все поля хранятся на уровне **организации**, но читаются и пишутся через существующие эндпоинты студии (`GET /studios/:studioId/settings` и `PATCH /studios/:studioId/settings`).

---

## API

### GET /studios/:studioId/settings

В ответ (в существующий объект) добавляются 4 поля:

```json
{
  "loyaltyMode": "PRESET",
  "globalBonusPaymentLimitPercent": 30,
  "referFriendEnabled": true,
  "referFriendInviteeRewardType": "DISCOUNT_PERCENT",
  "referFriendInviteeValue": 20,
  "referFriendReferrerRewardType": "PERCENT_OF_PAYMENT",
  "referFriendReferrerValue": 10,

  "marketingHoursStartHour": 9,
  "marketingHoursEndHour": 22,
  "paymentKaspiPhone": "+77011234567",
  "paymentKaspiCardHolder": "Иванов И. И.",
  "remotePaymentMethod": "PHONE_TRANSFER",
  "paymentIpRequisites": null,

  "nightHoldMinutes": 30,
  "dayInvoiceTaskDeadlineHours": 2,
  "nightReceiptTaskDeadlineHours": 12,

  "highPriorityGapMinutes": 60,
  "normalPriorityToleranceMinutes": 10
}
```

- `marketingHoursStartHour: number | null` — час начала смены отдела маркетинга, 0..23 (локальное время студии).
- `marketingHoursEndHour: number | null` — час окончания смены, 0..23. Допускается «переход через полночь» (например 22 → 6 означает «маркетинг на смене с 22:00 до 06:00 следующего дня»).
- `paymentKaspiPhone: string | null` — номер Kaspi, на который клиент переводит оплату в ночной режим.
- `paymentKaspiCardHolder: string | null` — ФИО держателя карты Kaspi (как показать клиенту).
- `remotePaymentMethod: "PHONE_TRANSFER" | "IP_ACCOUNT"` — способ удалённой оплаты в ночном режиме:
  - `PHONE_TRANSFER` — перевод по номеру;
  - `IP_ACCOUNT` — оплата на ИП (ссылкой из `paymentIpRequisites`).
- `paymentIpRequisites: string | null` — ссылка оплаты на ИП (пример: `https://pay.kaspi.kz/pay/arthp913`). Обязательна, когда выбран `IP_ACCOUNT`.
- `nightHoldMinutes: number | null` — сколько минут удерживаем предварительную бронь в ночном режиме, прежде чем крон её автоматически отменит. null → бэкенд применит дефолт 30.
- `dayInvoiceTaskDeadlineHours: number | null` — через сколько часов истекает дедлайн дневной задачи менеджеру на выставление счёта Kaspi. null → дефолт 2.
- `nightReceiptTaskDeadlineHours: number | null` — через сколько часов истекает дедлайн утренней задачи на сверку ночного чека с выпиской Kaspi. null → дефолт 12.
- `highPriorityGapMinutes: number | null` — «плотность записей»: максимальная длина окна (в минутах) между двумя подряд записями одного мастера, при которой все свободные слоты внутри этого окна получают **high**-приоритет в Nextbot `check_availability`. Сравнение по ≤. `null` → high-приоритет полностью выключен (Nextbot получает только `exact` / `normal` / `low`).
- `normalPriorityToleranceMinutes: number | null` — «допуск прилегания» для **normal**-приоритета (в минутах). Свободный слот получает `normal`, если его граница отстоит от границы записи мастера не более чем на это значение (в сторону свободного гэпа, без пересечения с записью). `0` или `null` — только впритык (текущее поведение). `high` всегда побеждает `normal`.

### PATCH /studios/:studioId/settings

Роли: **OWNER / DEPUTY_OWNER / DEVELOPER / SERVICE** (как и остальные настройки вкладки). Тело — частичное, можно передать только нужные поля:

```json
{
  "marketingHoursStartHour": 9,
  "marketingHoursEndHour": 22,
  "paymentKaspiPhone": "+77011234567",
  "paymentKaspiCardHolder": "Иванов И. И.",
  "remotePaymentMethod": "PHONE_TRANSFER",
  "paymentIpRequisites": null,
  "nightHoldMinutes": 30,
  "dayInvoiceTaskDeadlineHours": 2,
  "nightReceiptTaskDeadlineHours": 12,
  "highPriorityGapMinutes": 60,
  "normalPriorityToleranceMinutes": 10
}
```

Правила валидации (обрабатывает бэкенд, но дублируй на фронте, чтобы не ловить 400):

- `marketingHoursStartHour` и `marketingHoursEndHour` — целые числа **0..23** включительно.
- Пара «одно число + одно null» запрещена: либо оба числа, либо оба `null`.
- `marketingHoursStartHour !== marketingHoursEndHour` (иначе интервал пустой).
- Чтобы **очистить** рабочие часы маркетинга — отправь `{ "marketingHoursStartHour": null, "marketingHoursEndHour": null }`.
- Пустая строка в `paymentKaspiPhone` / `paymentKaspiCardHolder` трактуется бэкендом как очистка (становится `null`).
- `remotePaymentMethod` — одно из значений enum: `PHONE_TRANSFER` или `IP_ACCOUNT`.
- Пустая строка в `paymentIpRequisites` очищает значение.
- Если выбран `remotePaymentMethod = IP_ACCOUNT`, а `paymentIpRequisites` пустой/null — бэкенд вернёт 400.
- Для `IP_ACCOUNT` значение `paymentIpRequisites` должно быть ссылкой вида `https://pay.kaspi.kz/pay/<id>`.
- `nightHoldMinutes` — целое, **1..1440** (практический диапазон 5..120). Отправь `null`, чтобы бэкенд применил дефолт 30.
- `dayInvoiceTaskDeadlineHours` — целое, **1..48** (практический диапазон 1..8). `null` → дефолт 2.
- `nightReceiptTaskDeadlineHours` — целое, **1..48** (практический диапазон 4..24). `null` → дефолт 12.
- `highPriorityGapMinutes` — целое, **15..240** (практический диапазон 30..120). `null` → high-приоритет выключен.
- `normalPriorityToleranceMinutes` — целое, **0..30** (практический диапазон 0..20). `null` и `0` взаимозаменяемы — оба значат «только впритык».
- Если число в тайминге вне практического диапазона UI — блокируй на фронте, но в API его отправлять можно (валидатор пропустит, это «сломает себя сам», если пользователь знает что делает).

## UI во вкладке «Маркетинг»

Добавь блок **«Рабочие часы отдела маркетинга»** после существующих блоков «Лимит оплаты бонусами» и «Приведи подругу». Заголовок секции, короткое пояснение, затем форма.

### Короткое описание сверху блока

> Рабочие часы **отдела маркетинга** — когда менеджеры на смене и могут вручную выставлять клиентам счета Kaspi по заявкам от Nextbot.
> Не путать с графиком работы салона или сменами мастеров.
>
> В это время ИИ-агент передаёт оплату живому менеджеру. Вне этих часов клиент сразу получает статичные реквизиты Kaspi и 30 минут на оплату, после чего слот автоматически освобождается.

### Поля формы

1. **Переключатель** «Включить ночной режим оплаты» (boolean, только UI — на бэкенд это транслируется через значения часов):
   - Выключен → оба часа отправляются как `null`, поля ниже становятся неактивными. Маркетинг считается доступным 24/7.
   - Включён → показать поля ниже, обязательны оба часа.

2. **Начало смены отдела маркетинга** — селект часа (0..23). Подпись «Час начала», формат показа «09:00». По умолчанию 9.

3. **Конец смены отдела маркетинга** — селект часа (0..23). Подпись «Час окончания», формат показа «22:00». По умолчанию 22.
   - Подсказка: «Интервал задаётся по локальному времени студии. Поддерживается переход через полночь: например, 22 → 6 означает «смена с 22:00 до 06:00».»
   - Инлайн-ошибка если начало == конец.

4. **Телефон Kaspi** — текстовый инпут, маска под казахстанский номер (+7 ...), максимум 32 символа. Подпись «Номер, на который клиент переводит оплату».

5. **Получатель (ФИО)** — текстовый инпут, максимум 128 символов. Подпись «ФИО держателя карты Kaspi — показывается клиенту вместе с номером».

6. **Способ удалённой оплаты** — radio/select:
   - `Перевод по номеру` (`PHONE_TRANSFER`)
   - `Удалённая оплата на ИП` (`IP_ACCOUNT`)
   По умолчанию: `PHONE_TRANSFER`.

7. **Ссылка оплаты на ИП** — текстовое поле URL (до 500 символов), показывать/делать обязательным когда выбран `IP_ACCOUNT`.
   Подсказка: «Вставь ссылку Kaspi Pay, например: https://pay.kaspi.kz/pay/arthp913».

### Кнопки

- **«Сохранить»** — отправляет `PATCH /studios/:studioId/settings` с тем, что изменилось. После успеха — тост «Настройки сохранены».
- **«Отменить»** — сбрасывает форму до последнего значения с бэкенда.

### Подсказка под блоком (маленьким серым текстом)

> Если реквизиты Kaspi не заданы, а сейчас вне рабочих часов маркетинга — Nextbot всё равно задержит бронь, но клиенту попросит у менеджера реквизиты вручную. Рекомендуется заполнить оба поля.

## Подблок «Тайминги оплаты» (ниже «Рабочих часов маркетинга»)

Отдельная карточка в той же вкладке «Маркетинг». Три числовых поля с подсказками. Сохраняются одним `PATCH /studios/:studioId/settings`, можно слать только изменённые.

### Короткое описание сверху подблока

> Тонкая настройка сроков для Nextbot-потока оплаты. Если не уверен — оставь значения по умолчанию: 30 минут на ночную оплату, 2 часа на дневной счёт, 12 часов на утреннюю сверку чека.

### Поля

1. **Удержание ночной брони** — `nightHoldMinutes`, число минут.
   - Практический диапазон UI: **5..120**. Шаг 5.
   - По умолчанию 30. Кнопка «Сбросить к дефолту» отправляет `null`.
   - Подпись: «Сколько минут держим предварительную бронь после выдачи реквизитов Kaspi, прежде чем автоматически отменить, если клиент не прислал чек».

2. **Дедлайн дневной задачи** — `dayInvoiceTaskDeadlineHours`, число часов.
   - Практический диапазон UI: **1..8**. Шаг 1.
   - По умолчанию 2.
   - Подпись: «Через сколько часов задача менеджеру на выставление счёта Kaspi считается просроченной (влияет на сортировку и нотификации)».

3. **Дедлайн утренней сверки** — `nightReceiptTaskDeadlineHours`, число часов.
   - Практический диапазон UI: **4..24**. Шаг 1.
   - По умолчанию 12.
   - Подпись: «Через сколько часов после поступления ночного чека истекает дедлайн задачи на сверку с выпиской Kaspi».

### Поведение

- Рядом с каждым полем — бейдж **«дефолт»** (серый), если значение `null`. Если пользователь впечатал число — бейдж становится **«кастом»** (синий).
- Кнопка-ссылка рядом с полем: «сбросить к дефолту» → отправляет `null` на этот ключ.
- Валидация на фронте: если введённое число вне практического диапазона — показывай инлайн-предупреждение (но не блокируй отправку, бэкенд пропустит любое 1..48 / 1..1440).

### Подсказка под подблоком

> Значения хранятся на уровне **организации**. То, что ты сейчас меняешь в одном филиале, применится ко всем филиалам этой организации.

## Подблок «Плотность записей» (ниже «Таймингов оплаты»)

Отдельная карточка в той же вкладке «Маркетинг». Два числовых поля, управляющих **приоритетом свободных слотов** для Nextbot `check_availability`. Оба сохраняются тем же `PATCH /studios/:studioId/settings` (ключи `highPriorityGapMinutes` и `normalPriorityToleranceMinutes`).

### Короткое описание сверху карточки

> **Что настраиваем.** Когда Nextbot предлагает клиенту свободные слоты, он помечает их приоритетом: `exact` (идеальная щель под услугу), `high` (свободное «окно» между двумя подряд записями мастера — плотная тетриска), `normal` (слот, прилегающий к записи), `low` (всё остальное).
>
> Здесь два рычага: **ширина «плотного» окна** для high-приоритета и **допуск прилегания** для normal-приоритета.

### Поле 1 — «Интервал плотности» (`highPriorityGapMinutes`)

Максимальная длина окна между двумя подряд записями мастера, при которой все свободные слоты внутри этого окна считаются `high`.

- Практический диапазон UI: **30..120**. Шаг 15.
- По умолчанию **60**.
- Кнопка-переключатель «Выключить high-приоритет» (или чекбокс «Не использовать high»): при активации на сохранении уходит `null`, и поле становится неактивным. Рядом бейдж **«выкл.»**.
- Бейдж **«дефолт»** (серый), если `null`; **«кастом»** (синий), если пользователь задал число.

Пример подсказки под полем:

> Стоит 60 мин. У мастера две записи с промежутком 55 мин — все слоты в этом окне `high`. Если промежуток 75 мин — high в окне не будет: слоты впритык к записям станут `normal` (с учётом поля ниже), остальные — `low`.

### Поле 2 — «Допуск прилегания» (`normalPriorityToleranceMinutes`)

Расширяет область normal у границ каждой записи — даже если слот не прилегает **впритык**, он получит `normal`, пока расстояние до границы записи ≤ этого допуска.

- Практический диапазон UI: **0..20**. Шаг 5.
- По умолчанию **0** (только впритык).
- Не имеет «выключателя» — 0 и `null` эквивалентны.
- Бейдж **«впритык»** (серый) при 0/null; **«+N мин»** (синий) при положительном значении.

Пример подсказки под полем:

> Стоит 10 мин. Запись мастера 11:00–11:50. Слот 10:00–10:50 (кончается за 10 мин до записи) получит `normal`. Слот 09:55–10:45 (за 15 мин) — останется `low`. С другой стороны аналогично: 11:50–12:40 — `normal`, 12:05–12:55 — `low`.

### Взаимодействие high × normal

- `high` **всегда побеждает** `normal`. Если слот попал в «плотное» окно между двумя записями, где окно ≤ `highPriorityGapMinutes` — он получит `high` независимо от допуска.
- Допуск срабатывает только там, где high не применился: либо high выключен целиком, либо окно шире порога, либо запись «одинокая» (нет пары с соседней в пределах порога).

### Поведение

- Пересчёт приоритетов происходит **на лету** при каждом запросе слотов — менять обе настройки можно в любой момент, история записей не портится.
- Настройки считаются «per-мастер»: окна и прилегания ищутся между записями **одного** мастера, не смешивая расписания разных.
- Допуск работает **только в сторону свободного гэпа** и никогда не даёт слоту «залезть» внутрь записи.
- Валидация на фронте: `highPriorityGapMinutes` — 15..240; `normalPriorityToleranceMinutes` — 0..30.

### Подсказка под подблоком

> Значения хранятся на уровне **организации** — применятся ко всем филиалам. Для плотной тетриски в студиях с высокой загрузкой: `highPriorityGapMinutes` 45–60, `normalPriorityToleranceMinutes` 5–10. Для лайтовых графиков: поднимай «интервал плотности» до 90–120 или выключай high, а «допуск прилегания» оставляй 0.

---

## Права доступа

Блок редактируется тем же списком ролей, что и остальные настройки маркетинга:

- **DEVELOPER, OWNER, DEPUTY_OWNER, SERVICE** — могут видеть и менять.
- Прочие роли (ADMIN, MANAGER, MASTER, и т. д.) — не должны видеть блок совсем.

---

## Ответы бэкенда на ошибки

- **400 Bad Request**
  - «Задайте оба часа рабочего времени отдела маркетинга (marketingHoursStartHour и marketingHoursEndHour) или оба null».
  - «marketingHoursStartHour не может совпадать с marketingHoursEndHour».
  - Валидации `class-validator` (число, 0..23, длина строки).

- **403 Forbidden** — роль не из списка.
- **404 Not Found** — студия не найдена.

Покажи пользователю текст ошибки из `response.message` (если массив — первое значение).
