# История движения товаров — промпт для Lovable

## Задача

Добавить отображение **истории движения товаров** на экранах склада:

1. **На экране центрального склада** — раздел/вкладка «История»: куда и когда уходил товар с центрального склада.
2. **На экране склада филиала** — раздел/вкладка «История»: что приходило на склад (перемещения с центра, приходы) и что списывалось.

Данные брать только из API (бэкенд уже отдаёт готовые списки).

---

## API

Все запросы с заголовком: `Authorization: Bearer <access_token>`.

### 1. История центрального склада

**URL:** `GET /warehouse/central/history`  
**Доступ:** только владелец (OWNER) и заместитель владельца (DEPUTY_OWNER).

**Ответ 200** — массив записей (отгрузки с центра), от новых к старым:

```json
[
  {
    "id": "uuid",
    "type": "TRANSFER_OUT",
    "productId": "uuid",
    "product": {
      "id": "uuid",
      "name": "Воск для депиляции",
      "description": null,
      "article": "ART-001",
      "unit": "KG"
    },
    "quantity": 5,
    "createdAt": "2026-02-23T12:00:00.000Z",
    "createdByUserId": "uuid",
    "createdByName": "Иван Иванов",
    "toWarehouseId": "uuid",
    "toWarehouseName": "Студия на Ленина"
  }
]
```

**Что выводить в таблице/карточках:** дата и время (`createdAt`), товар (`product.name`), количество и единица (`quantity` + `product.unit`), «Куда» — `toWarehouseName`, «Кто оформил» — `createdByName` (или «—», если null). Тип операции можно подписывать как «Перемещение на филиал» или «Отгрузка».

---

### 2. История склада филиала

**URL:** `GET /studios/:studioId/warehouse/history`  
**Параметр:** `studioId` — ID текущего филиала (студии).  
**Доступ:** по тем же правилам, что и склад филиала (владелец, зам, менеджер, админ своего филиала).

**Ответ 200** — массив записей (все движения по этому складу), от новых к старым:

```json
[
  {
    "id": "uuid",
    "type": "TRANSFER_IN",
    "productId": "uuid",
    "product": { "id": "uuid", "name": "Воск для депиляции", "unit": "KG" },
    "quantity": 10,
    "createdAt": "2026-02-23T14:00:00.000Z",
    "createdByUserId": "uuid",
    "createdByName": "Мария Петрова"
  },
  {
    "id": "uuid",
    "type": "RECEIPT",
    "productId": "uuid",
    "product": { "id": "uuid", "name": "Крем", "unit": "ML" },
    "quantity": 5,
    "createdAt": "2026-02-23T13:00:00.000Z",
    "createdByUserId": "uuid",
    "createdByName": "Иван Иванов"
  },
  {
    "id": "uuid",
    "type": "WRITE_OFF",
    "productId": "uuid",
    "product": { "id": "uuid", "name": "Воск", "unit": "KG" },
    "quantity": -2,
    "createdAt": "2026-02-23T12:00:00.000Z",
    "createdByUserId": "uuid",
    "createdByName": "Иван Иванов",
    "forStaffUserId": "uuid",
    "forStaffName": "Анна Смирнова"
  }
]
```

**Типы записей (`type`):**

| type         | Значение в UI (пример)     | quantity              |
|-------------|----------------------------|------------------------|
| `TRANSFER_IN` | Перемещение с центра       | положительное          |
| `RECEIPT`     | Приход                     | положительное          |
| `WRITE_OFF`   | Списание                   | отрицательное (например −2) |

**Что выводить в таблице/карточках:** дата и время (`createdAt`), тип операции (по `type` — см. таблицу выше), товар (`product.name`), количество с учётом знака (для списания показывать как «−2» или «Списание 2» + единица), «Кто оформил» — `createdByName` (или «—», если null). Для записей **`TRANSFER_IN` и `RECEIPT`** поля `forStaffUserId` и `forStaffName` всегда `null`. Для **`WRITE_OFF`** — колонка **«В пользу мастера»**: показывать `forStaffName` (или «—», если `null` у старых записей до внедрения поля).

У записей перемещения и прихода в ответе также приходят `forStaffUserId: null` и `forStaffName: null` — это нормально, колонку можно скрывать или показывать «—».

Единицу подставлять из `product.unit`: KG → «Кг», PCS → «шт», ML → «мл».

## UI/UX

- На экране **центрального склада**: кнопка или вкладка «История движения» → при переходе вызывать `GET /warehouse/central/history` и показать таблицу (или список карточек).
- На экране **склада филиала**: кнопка или вкладка «История движения» → при переходе вызывать `GET /studios/:studioId/warehouse/history` и показать таблицу (или список карточек).
- Даты форматировать в локаль пользователя (например, «23.02.2026, 14:00»).
- Пустой список — показывать сообщение вида «История движений пока пуста».
- Ошибки 403/404/5xx обрабатывать и показывать понятное сообщение пользователю.
