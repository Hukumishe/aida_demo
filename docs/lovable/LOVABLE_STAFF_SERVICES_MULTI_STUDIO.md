# Услуги мастера во всех филиалах

## Поведение бэкенда

Список услуг мастера **единый по организации**: привязки хранятся в `staff_services` по филиалам, но:

1. **Добавление** (`POST /staff/:id/services`) — услуга создаётся во **всех** филиалах, где работает мастер (основной `studioId` + `user_studio_memberships`), если услуга там не отключена.
2. **Удаление** (`DELETE /staff/:id/services/:serviceId`) — снимается **везде**.
3. **Новая запись** (`GET /services?studioId=…&staffUserId=…`) — показываются все услуги мастера из объединения, доступные **в выбранном** филиале.

Профиль мастера (`GET /staff/:id/profile`) в `services` отдаёт **уникальный** список услуг (без дублей по филиалам).

## UI (Lovable)

- В карточке сотрудника достаточно настроить услуги **один раз** (в любом филиале из списка «где работает»).
- В «Новой записи» при смене филиала список услуг мастера подтянется автоматически, если услуга не отключена в этом филиале.
- Если услуга отключена только в одном филиале — в других она останется; в отключённом филиале не появится в выпадающем списке.

## Существующие данные

Достаточно **один раз** открыть мастера в CRM и сохранить услуги (или добавить/удалить одну услугу) — новые правила синхронизируют филиалы. Либо дождаться деплоя: чтение для записи уже использует объединение по всем филиалам.
