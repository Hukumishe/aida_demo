# Промпт для Lovable: таймзона организации, даты, waitlist

Скопируй блок ниже в Lovable как задачу на обновление фронта под актуальный бэкенд (`aida_demo`).

---

## Контекст

Бэкенд добавил поле **`ianaTimezone`** у организации (IANA, например `Asia/Aqtobe`, `Asia/Almaty`), эндпоинты для DEVELOPER, нормализацию календарных дат и исправление ошибки **`400 Invalid local time …`** при фильтрах по дате (в т.ч. лист ожидания). В JSON ответах по-прежнему **вырезается** ключ `timezone` (глобальный интерцептор), поэтому у организации используется именно **`ianaTimezone`**, не `timezone`.

## Задачи для фронта

### 1. Организации (только роль DEVELOPER)

- В списке и карточке организации показывать **`ianaTimezone`** из `GET /organizations` и `GET /organizations/:organizationId`.
- При создании организации (`POST /organizations`) опционально передавать **`ianaTimezone`** (строка IANA).
- Добавить смену таймзоны: **`PATCH /organizations/:organizationId`** с телом `{ "ianaTimezone": "<IANA>" }` (можно только это поле).
- Валидация на UI: список зон через `Intl.supportedValuesOf('timeZone')` или поиск с автодополнением; не подставлять произвольный текст без проверки.
- Не ожидать у организации поле **`timezone`** — его нет.

### 2. Параметры даты в запросах (критично)

Для query-параметров **`date`** (записи по дню, лист ожидания и любые аналогичные фильтры):

- Передавать **только календарную дату в формате `YYYY-MM-DD`** (например `2026-04-21`).
- **Не** передавать `2026-04-21 00:00:00` без буквы `T` в query — это ломало сопоставление дат на бэкенде. Если нужен момент времени — используй ISO с **`T`**: `2026-04-21T00:00:00.000Z`; для **фильтра по дню** достаточно **`YYYY-MM-DD`**.

Проверь места: waitlist, журнал записей, дашборд при пользовательском диапазоне дат — везде унифицировать.

### 3. Создание филиала

- При **`POST /studios`** если поле **`timezone`** не отправлять, бэкенд подставит **`ianaTimezone`** организации. Имеет смысл в UI подсказать: «по умолчанию как у организации» и при смене организационной таймзоны не забывать про новые филиалы.

### 4. Регрессии

- После деплоя бэка с миграциями убедиться, что лист ожидания и список записей по дате не отдают **400** для зон вроде **`Asia/Aqtobe`**.
- Ошибки API показывать текстом из ответа (`message`), не глушить.

## Справка по API (кратко)

| Действие | Метод и путь | Тело / примечание |
|----------|----------------|-------------------|
| Список организаций | `GET /organizations` | только DEVELOPER |
| Организация | `GET /organizations/:organizationId` | в ответе есть `ianaTimezone` |
| Создать организацию | `POST /organizations` | `{ "name", "slug?", "ianaTimezone?" }` |
| Обновить организацию | `PATCH /organizations/:organizationId` | `{ "ianaTimezone" }` |
| Создать филиал | `POST /studios` | `timezone?` — иначе берётся из орг. |
