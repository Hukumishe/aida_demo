# Промпт для Lovable: модалка «Запись в удобное время» (как в админке)

Скопируйте блок **«Задача для Lovable»** в чат Lovable. Ниже — справка по бэкенду AIDA (текущая логика создания клиента в CRM).

---

## Справка: как в админке создаётся клиент (AIDA)

- Эндпоинт: **`POST /clients`**
- Авторизация: **`Authorization: Bearer <accessToken>`** (как у любого экрана CRM)
- Организация берётся из JWT (для **DEVELOPER** можно передать `?organizationId=...` — как в других экранах админки)
- Тело запроса — **`CreateClientDto`** (то же, что форма «Новый клиент»)

Обязательные поля для создания: **`firstName`**, **`phone`**.  
Опционально: **`lastName`**, **`patronymic`**, **`instagram`**, **`notes`**, **`gender`**, **`birthDate`**, реферальные поля, в т.ч. **`referralLinkId`**.

**Источник (маркетинг):** текст «Источник» в карточке клиента хранится в поле ответа **`registrationSource`**. Его **нельзя** задать произвольной строкой при создании с рефералкой: при передаче **`referralLinkId`** сервер сам подставляет **`registrationSource` = `sourceName`** из маркетинговой ссылки и привязывает **`studioReferralLinkId`**. Это защита от подделки источника.

Публичная проверка ссылки до отправки формы:

- **`GET /studios/:studioId/referral-links/resolve/:linkId`** (без авторизации)
- Ответ при успехе: `{ valid: true, sourceName, ... }` — используйте **`sourceName`** для подписи поля «Источник» в UI.

**Важно для лендинга:** типичный публичный лендинг **не** имеет JWT пользователя CRM. Чтобы сохранить клиента в AIDA так же, как админка, нужен один из вариантов: серверный прокси (backend-for-frontend) с сервисным токеном / отдельный публичный эндпоинт на стороне AIDA / вызов из уже авторизованной части приложения. В задаче ниже сфокусируйтесь на **совпадении полей и payload с `CreateClientDto`**; способ авторизации согласуйте с бэкендом.

---

## Задача для Lovable

### 1. Контекст UI

Есть модальное окно **«Запись в удобное время»** с полями:

- Ваше имя  
- Телефон (маска)  
- Удобное время  
- Комментарий (необязательно)  
- Кнопка «Отправить заявку»

Нужно **доработать** это окно, не ломая визуальный стиль (градиентная кнопка, иконки, дисклеймер внизу).

### 2. Поле «Источник» (реферальная ссылка)

- Поддержать вход по URL с параметром рефералки, например **`?ref=<referralLinkId>`** (id маркетинговой ссылки из CRM).
- При наличии **`ref`** при загрузке страницы вызвать  
  **`GET {API}/studios/{studioId}/referral-links/resolve/{linkId}`**  
  где **`studioId`** — текущий филиал лендинга (как в остальных запросах к API).
- Если **`valid: true`**:
  - **Открывать это же модальное окно** при заходе по ссылке (как будто пользователь нажал «Записаться»), чтобы сразу попасть в форму.
  - Добавить в форму поле **«Источник»**: показать **`sourceName`** (read-only или disabled), подпись вида «Источник: …».
- При отправке формы в теле создания клиента передавать **`referralLinkId`** = значение из **`ref`**. Не отправлять «источник» отдельным произвольным текстом вместо id ссылки — иначе бэкенд не зафиксирует маркетинговый источник так же, как в админке.

Если **`ref`** нет или resolve вернул **`valid: false`** — поле «Источник» не показывать, **`referralLinkId`** не передавать.

### 3. Соответствие полей формы и API (как в админке)

Цель — собрать объект, совместимый с **`CreateClientDto`**, по смыслу как «новый клиент» в CRM.

| Поле в модалке | Как отдать в API |
|----------------|------------------|
| **Ваше имя** | Минимум **`firstName`**: первое слово или вся строка, если фамилию не выделяем. По желанию UX: если два слова — **`firstName`** = первое слово, **`lastName`** = остаток (как часто делают в админке при раздельном вводе). |
| **Телефон** | **`phone`**: нормализовать к одному формату (как в CRM), без потери цифр и кода страны. |
| **Удобное время** | Не отдельное поле в DTO. Включить в **`notes`** с явной меткой, см. шаблон ниже. |
| **Комментарий** | Часть **`notes`** (дописать к блоку про удобное время). |
| **Источник (рефералка)** | Только **`referralLinkId`** при наличии `ref`; отображаемый текст — из resolve, не как отдельное поле API. |

Рекомендуемый шаблон **`notes`** (чтобы администратору в карточке было понятно, откуда заявка):

```text
[Заявка с лендинга]
Удобное время: <текст из поля «Удобное время»>
Комментарий: <текст из поля «Комментарий» или «—», если пусто>
```

При пустом «Удобное время» можно опустить строку или писать «не указано».

### 4. Опционально: отчество и Instagram (как в карточке клиента)

Если нужно полное совпадение с карточкой клиента в CRM:

- Добавить необязательные поля **«Отчество»** → **`patronymic`**, **«Instagram»** → **`instagram`** (те же имена, что в админке и в Swagger).
- Разместить под основным блоком или в «Дополнительно», чтобы не перегружать лид-форму.

### 5. Отправка и ошибки

- При успешном создании клиента показать success-состояние (toast / текст в модалке) и закрыть или оставить «Спасибо».
- При ошибке **409 / дубликат телефона** (клиент уже есть в организации) — показать дружелюбное сообщение: «Этот номер уже зарегистрирован, мы свяжемся с вами» или предложить позвонить (текст согласовать с владельцем). Это соответствует поведению **`POST /clients`** при существующем номере.

### 6. Не делать

- Не подменять **`referralLinkId`** произвольной строкой «источник» — источник для маркетинговой ссылки задаётся только через id ссылки на бэкенде.
- Не хранить «удобное время» в отдельном поле БД, если бэкенд не добавлен — достаточно **`notes`**, как выше.

---

После внедрения проверьте сценарий: заход по ссылке с **`?ref=`** → модалка открыта → «Источник» заполнен названием → отправка → в CRM у клиента заполнены **`registrationSource`**, при необходимости **`patronymic` / `instagram`**, в **`notes`** — удобное время и комментарий.
