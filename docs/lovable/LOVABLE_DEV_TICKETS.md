# Промпт для Lovable: тикеты разработчикам (чат, статусы, архив)

Скопируйте блок **«Промпт»** ниже целиком в чат Lovable.

Дополнительно по загрузке картинок: `LOVABLE_LANDING_IMAGE_UPLOAD.md` (тот же `POST /upload/landing` → URL в массиве `screenshotUrls`).

---

## Промпт

### Задача

Реализуй раздел **«Тикеты»** для бэкенда AIDA (NestJS): обращения сети салонов к **платформенным разработчикам** с описанием проблемы, шагами воспроизведения и скриншотами, **чатом** внутри тикета и **статусами**. Разделение ролей и экранов — строго по ТЗ ниже.

### Авторизация

- Все запросы с **`Authorization: Bearer <accessToken>`** (после логина).
- Роль и контекст: **`GET /auth/me`** → `user.role`, `user.organizationId` (для сетевых ролей).

---

### Кто что видит и делает

| Роль | Навигация | Действия |
|------|-----------|----------|
| **`DEVELOPER`** | Пункт меню **«Тикеты»** (очередь платформы) | Видит **все** тикеты **всех** организаций. Меняет статус (`IN_PROGRESS`, `COMPLETED`). Пишет в чат. |
| **`OWNER`**, **`DEPUTY_OWNER`** | Пункт **«Тикеты»** (своя сеть) | **Создают** тикеты. Видят только тикеты **своей** `organizationId`. Пишут в чат. **Не** меняют статус. |
| **`SERVICE`** | Тот же пункт «Тикеты» (своя сеть) | Как у владельца по **просмотру и чату**, **без создания** тикетов (если бэкенд вернёт 403 на `POST` — скрой кнопку «Создать»). |
| Остальные роли | Пункт **не показывать** | Прямой заход на URL → редирект или 403. |

---

### API (базовый URL из env, например `VITE_API_URL`)

#### Создать тикет

- **`POST /dev-tickets`**
- **Только `OWNER` и `DEPUTY_OWNER`** (иначе 403).
- Тело:

```json
{
  "title": "string",
  "problemDescription": "string",
  "howItHappened": "string (optional)",
  "screenshotUrls": ["https://...", "https://..."]
}
```

Скриншоты: сначала загрузка файла на **`POST /upload/landing`** (`multipart/form-data`, поле **`file`**), в ответе **`{ "url": "..." }`** — собери массив URL и передай в `screenshotUrls` (см. `LOVABLE_LANDING_IMAGE_UPLOAD.md`).

#### Список тикетов

- **`GET /dev-tickets?bucket=active`** или **`GET /dev-tickets?bucket=archive`**
- Query **`bucket` обязателен**:  
  - **`active`** — статусы `OPEN` и `IN_PROGRESS` (рабочая очередь).  
  - **`archive`** — только **`COMPLETED`** (выполненные, отдельный экран/вкладка, чтобы не засорять основной список).
- **DEVELOPER** — все организации. **OWNER / DEPUTY_OWNER / SERVICE** — только своя организация.

Ответ — массив тикетов с полями вроде: `id`, `title`, `status`, `createdAt`, `organization` (`id`, `name`), `createdBy`, счётчик сообщений (`_count.messages` у разработчика и т.д. — ориентируйся на фактический JSON).

#### Карточка тикета с чатом

- **`GET /dev-tickets/:id`**
- Детали + **массив `messages`** (по времени), у сообщения есть **`user`** с ролью и **`staffProfile`** (имя для подписи).
- Доступ: DEVELOPER — любой тикет; сетевые роли — только если тикет принадлежит их `organizationId`.

#### Сообщение в чат

- **`POST /dev-tickets/:id/messages`**
- Тело: **`{ "body": "текст сообщения" }`**
- Пока статус тикета **не** `COMPLETED`. Если тикет завершён — бэкенд вернёт **400** («чат только для чтения»): **скрой поле ввода и кнопку отправки**, историю показывай.

#### Смена статуса (только разработчик)

- **`PATCH /dev-tickets/:id/status`**
- Тело: **`{ "status": "IN_PROGRESS" }`** или **`{ "status": "COMPLETED" }`**
- **Только `DEVELOPER`** (иначе 403).
- При переходе в **`COMPLETED`** чат закрывается для новых сообщений; на карточке показывай **`completedAt`**, при наличии — **`completedBy`**.

Статусы: **`OPEN`** (новый), **`IN_PROGRESS`** (в работе), **`COMPLETED`** (выполнен, в архиве).

### UX: экран разработчика (`DEVELOPER`)

1. Вкладки или подразделы: **«Активные»** (`bucket=active`) и **«Архив»** (`bucket=archive`).
2. Таблица/список: заголовок, организация, статус, дата, число сообщений; клик → детальная страница.
3. На детальной странице: полное описание (`problemDescription`, `howItHappened`), галерея скриншотов по URL (открытие в новой вкладке / lightbox).
4. Чат снизу или справа; ввод текста, если статус ≠ `COMPLETED`.
5. Блок **«Статус»**: кнопки или селект **«В работе»** / **«Выполнен»** → `PATCH .../status`. После **«Выполнен»** обнови данные и заблокируй ввод в чате.

---

### UX: экран сети (`OWNER` / `DEPUTY_OWNER` / `SERVICE`)

1. Те же **«Активные»** и **«Архив»** через `bucket`.
2. Кнопка **«Создать тикет»** — только для **`OWNER`** и **`DEPUTY_OWNER`** (форма: заголовок, суть проблемы, как воспроизвести, несколько загрузок картинок → `screenshotUrls`).
3. Список только по своей организации; деталька + чат; **без** управления статусом (только просмотр статуса и переписка).
4. Для **`SERVICE`**: без создания, если 403 на `POST` — не показывай форму создания.

---

### Ошибки и граничные случаи

- **403** — нет прав (не та роль или чужая организация); не ретраить без смены пользователя/контекста.
- **400** на сообщение при завершённом тикете — UI уже не должен отправлять (read-only чат).
- Пустой архив: пустое состояние «Нет выполненных тикетов».

### Стили

Соблюдай текущую дизайн-систему приложения (типографика, отступы, тема). Статусы можно выделить бейджами: открыт / в работе / выполнен.
