# Промпт для Lovable: интеграция с AIDA (организации, studioId, мультиарендность)

Скопируйте блок ниже целиком в чат Lovable (или используйте как системный контекст для проекта).

---

## Контекст бэкенда

Подключайся к **REST API NestJS** (AIDA). Данные разделены по **организациям (tenant)**: сеть салонов = одна **Organization**. У каждой организации много **филиалов (Studio)**. Каталог услуг, CRM-клиенты (в рамках орг), маркетинг, склад, лояльность, «приведи друга» — на уровне **организации**; расписание, записи, часть уведомлений — с привязкой к **филиалу (`studioId`)**.

Базовый URL API храни в переменной окружения (например `VITE_API_URL` / настройки Lovable), **без** лишнего суффикса `/api`, если бэкенд так задеплоен.

---

## Авторизация

- После **`POST /auth/login`** с `{ "phone", "password" }` сохраняй **`accessToken`** и при необходимости **`refreshToken`**.
- Все защищённые запросы: заголовок **`Authorization: Bearer <accessToken>`**.
- Обновление токена: **`POST /auth/refresh`** с телом `{ "refreshToken" }`.
- Текущий пользователь: **`GET /auth/me`** — в ответе обязательно используй:
  - **`user.organizationId`** — id организации пользователя;
  - **`user.studioId`** — id филиала или `null` (сетевые роли без привязки к одному филиалу);
  - **`user.role`** — одна из ролей, включая новую **`DEVELOPER`**;
  - при наличии — **`user.organization`** (id, name, slug).

Во всём UI храни **`organizationId` и `studioId` в состоянии приложения** (контекст React / store) и подставляй их в URL там, где API требует `:studioId`.

---

## Роли (важно для навигации и прав)

- **`DEVELOPER`** — платформа: видит **все** организации и **все** филиалы; отдельные эндпоинты только для этой роли (см. ниже). Не ограничивай выбор филиала только `user.studioId`.
- **`OWNER` / `DEPUTY_OWNER` / `SERVICE` / `MANAGER`** — работа в рамках своей организации; список филиалов обычно из **`GET /studios`** (для OWNER/MANAGER — филиалы своей орг).
- **`ADMIN` / `MASTER`** — привязка к одному филиалу (`user.studioId`); не показывай чужие филиалы.

Если роль **`DEVELOPER`**, покажи в приложении **отдельный раздел «Организации»** (создание и список). Для остальных ролей этот раздел не вызывай (получишь 403).

---

## Организации (только DEVELOPER)

Используй только если `user.role === 'DEVELOPER'`:

| Действие | Метод и путь | Тело / примечание |
|----------|----------------|-------------------|
| Список организаций | `GET /organizations` | — |
| Одна организация | `GET /organizations/:organizationId` | — |
| Создать организацию | `POST /organizations` | `{ "name": string, "slug?": string }` — slug опционально, латиница/цифры/дефис |

После создания организации **создай филиал** (см. ниже), передав **`organizationId`** в теле, если API это поддерживает для DEVELOPER.

---

## Филиалы (studios)

- **Список филиалов:** `GET /studios` — для **DEVELOPER** бэкенд возвращает **все** филиалы всех организаций; для OWNER/MANAGER — филиалы **своей** организации; для ADMIN — обычно свой филиал.
- **Один филиал:** `GET /studios/:studioId` — доступ только к филиалам, разрешённым роли (у DEVELOPER — любой существующий id).
- **Создать филиал:** `POST /studios` — тело `{ "name", "address?", "timezone?", "organizationId?" }`.  
  - Для **DEVELOPER**: если нужно создать филиал в **конкретной** организации, передай **`organizationId`** (созданную из `/organizations`).  
  - Для OWNER/DEPUTY/SERVICE филиал создаётся в **организации пользователя**, поле `organizationId` не требуется.
- **Изменить название / адрес:** `PATCH /studios/:studioId` — `{ "name"?, "address"? }`. Роли **OWNER**, **DEPUTY_OWNER**, **DEVELOPER**. Флаги `permissions.canEditProfile` / `canDelete` в **`GET /studios/:studioId`**.
- **Удалить филиал:** `DELETE /studios/:studioId` — **только DEVELOPER**; филиальные сотрудники удаляются, сетевые роли (OWNER, MANAGER, MARKETER…) не затрагиваются.

**Никогда не подставляй** в URL литералы вроде `{studioId}` или `{{studioId}}` — реальный id бери из **`GET /studios`** или из **`user.studioId`**.

---

## Настройки и лояльность (уровень организации, путь через studio)

Эндпоинты привязаны к **`:studioId`**, но меняют настройки **организации** этого филиала:

- `GET /studios/:studioId/settings` — лимит бонусов, «приведи друга»;
- `PATCH /studios/:studioId/settings`;
- `GET /studios/:studioId/loyalty` / `PUT /studios/:studioId/loyalty` — режим PRESET/CUSTOM и уровни.

В UI подписывай, что это **настройки сети (организации)**, а не одного филиала в бизнес-смысле, если в продукте так принято.

---

## Клиенты, услуги, записи

- Пути вида **`/studios/:studioId/clients`**, **`/studios/:studioId/services`**, **`/studios/:studioId/appointments`** — всегда подставляй выбранный **`studioId`**.
- Клиенты уникальны по **телефону в пределах организации** (не глобально по всей базе).
- Услуги и категории — на уровне организации; список по филиалу тянет каталог **организации** этого филиала.

---

## Nextbot / AI (если нужен отдельный экран)

Все функции бота сгруппированы под префиксом **`/nextbot`** (например `GET /nextbot/context`, `GET /nextbot/studios/:studioId/...`). Тот же Bearer-токен. Подробнее — см. документ **`NEXTBOT_ARGS_RESULT_GLOSSARY.md`** в репозитории бэкенда.

---

## Обработка ошибок

- **403** — часто несовпадение организации/филиала или недостаточно прав; не повторяй запрос с тем же контекстом.
- **400** с текстом про плейсхолдер **`studioId`** — в URL попал шаблон вместо id; сначала **`GET /studios`** или **`GET /nextbot/context`**.

---

## Что сделать в UI (чеклист для Lovable)

1. После логина сохранить **`organizationId`**, **`studioId`**, **`role`** из **`/auth/me`**.
2. Добавить **переключатель филиала** (dropdown), если у пользователя доступно несколько студий из **`GET /studios`**; выбранный id использовать во всех запросах с `:studioId`.
3. Для **`DEVELOPER`**: экран **«Организации»** (`GET/POST /organizations`) и при создании филиала в нужной орг — **`POST /studios`** с **`organizationId`**.
4. Не смешивать данные разных организаций в одном списке без явного фильтра (для DEVELOPER показывай **organizationId** рядом с филиалом в списке, если бэкенд отдаёт поле на студии).
5. Учесть **`GET /auth/me` → user.organization`** для отображения названия сети.

---

## Конец промпта

Используй **fetch/axios** с базовым URL из env, **credentials** при необходимости CORS настроен на стороне бэкенда. Стиль UI — по дизайн-системе проекта Lovable; логика — строго по эндпоинтам выше.
