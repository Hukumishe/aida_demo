# Карточка «Детали записи» — комментарий и предоплата (промпт для Lovable)

**Задача:** в модальном окне **«Детали записи»** (`AppointmentDetailsModal`) добавить две строки в том же стиле, что клиент / услуга / дата / мастер / допродажи (иконка слева + подпись + значение).

**Не трогать:** сетку журнала, создание записи (если там уже есть поля — можно синхронизировать позже), автосообщения Nextbot, другие разделы CRM.

**Бэкенд уже готов** — менять API не нужно.

Справка: `LOVABLE_APPOINTMENT_LOG.md` (разделы GET списка записей и PATCH).

---

## Где в UI

Модалка **«Детали записи»** (скрин: заголовок, статус «Подтверждена», блоки Зарина / услуга / дата / мастер / допродажи, статус записи, кнопки «Клиент пришёл» / «Завершить» / «Не пришёл»).

**Вставить две новые строки** после блока **«Мастер»** и **до** блока **«Допродажи»** (или сразу после допродаж — главное, чтобы обе были видны без прокрутки на типичном экране).

Порядок:

1. … Мастер  
2. **Комментарий** ← новое  
3. **Предоплата** ← новое  
4. Допродажи  
5. …

## Данные с API

Записи приходят из:

`GET /studios/:studioId/appointments?date=YYYY-MM-DD`

В каждом объекте записи уже есть:

| Поле API | Тип | Описание |
|----------|-----|----------|
| `comment` | `string \| null` | Комментарий к записи |
| `prepaymentAmount` | `number \| null` | Сумма предоплаты в **тенге** (целое число) |

Если полей нет в ответе (старый кэш) — считать `null`.

---

## Строка «Комментарий»

**Иконка:** MessageSquare / MessageCircle / StickyNote (как у остальных — outline, серый).

**Подпись:** `Комментарий`

**Отображение (режим просмотра):**

- Если `comment` не пустой — показать текст (многострочно, `whitespace-pre-wrap`).
- Если пусто — серый текст *«Нет комментария»*.

**Редактирование:**

- Роли с правом менять запись: **OWNER**, **DEPUTY_OWNER**, **MANAGER**, **ADMIN** (как для переноса/отмены в вашем CRM; **MASTER** — только просмотр, без редактирования, если так сделано для остальных полей карточки).
- Клик по строке или кнопка «Изменить» (карандаш) → `textarea` на 2–4 строки.
- Кнопки **«Сохранить»** / **«Отмена»** локально в строке или внизу модалки.
- Сохранение:

```http
PATCH /appointments/:id
Authorization: Bearer <token>
Content-Type: application/json

{ "comment": "Текст комментария" }
```

- Очистка: `{ "comment": "" }` — бэкенд сохранит `null`.
- После успеха: обновить локальный `selectedAppointment`, вызвать `onUpdate()` (перезагрузить журнал).

---

## Строка «Предоплата»

**Иконка:** Banknote / Wallet / Coins.

**Подпись:** `Предоплата`

**Отображение (режим просмотра):**

- Если `prepaymentAmount != null` и `> 0` — **`{amount} ₸`** (формат с пробелом тысяч: `4 000 ₸`).
- Если нет — *«Не указана»*.

Дополнительно (опционально, мелким серым текстом): если в записи есть `forfeitedPrepaymentAmount > 0`, показать *«Сгоревшая предоплата: X ₸»* **только для чтения** (не редактировать).

**Редактирование:**

- Те же роли, что для комментария.
- Поле ввода: **целое число ≥ 0**, суффикс **₸**, placeholder `0`.
- Пустое поле при сохранении → не передавать `prepaymentAmount` или передать `null` / не слать поле — на усмотрение; если передаёте `0`, бэкенд сохранит 0.
- Сохранение:

```http
PATCH /appointments/:id

{ "prepaymentAmount": 4000 }
```

- Можно сохранять **комментарий и предоплату одним PATCH**, если пользователь изменил оба:

```json
{
  "comment": "Клиент просит мастера Майру",
  "prepaymentAmount": 4000
}
```

- После успеха — как для комментария.

**Важно:** предоплата влияет на сценарии «Опоздал», no-show, отмена &lt; 4 ч — не дублировать эту логику на фронте, только ввод суммы.

## UX

- Стиль строк — **как у «Мастер» / «Допродажи»**: тот же `flex`, отступы, размер шрифта, цвет подписи.
- При сохранении: disabled + спиннер на кнопке, toast «Сохранено» / ошибка из `message` ответа 400.
- Не закрывать модалку после сохранения комментария/предоплаты.
- На мобильной ширине — textarea и input на всю ширину.
