# Промпт для Lovable: лендинг → «Предварительная бронь» в журнале

Скопируйте блок **«Промпт»** ниже в чат Lovable **целиком**.

**Не** проси переделать всю форму записи на лендинге — задача **одна**: корректно показывать и обрабатывать статус **`TENTATIVE`** для записей с сайта.

Backend AIDA **уже обновлён**: `POST /landing/booking-request` с выбранным слотом создаёт запись со статусом **`TENTATIVE`**, не `BOOKED`.

---

## Промпт

### Задача (одна)

Записи с **публичного лендинга** (форма «Запись в удобное время», `createdSource: LANDING`) в **журнале CRM** должны отображаться как **«Предварительная бронь»** (`TENTATIVE`), а **не** как «Подтверждена» / «Забронировано» (`BOOKED`).

Менеджер **подтверждает** такую запись в CRM → статус **`BOOKED`**.

**Не делать:** менять бэкенд, эндпоинт `POST /landing/booking-request`, логику слотов, Nextbot — всё уже работает.

---

### Backend (готов, не трогать)

| Поле | Значение для записи с лендинга |
|------|--------------------------------|
| `createdSource` | `LANDING` |
| `status` | **`TENTATIVE`** (до подтверждения менеджером) |
| `bookedAt` | `null` (проставляется при переходе в `BOOKED`) |

Справочник подписей статусов (если ещё не подключён):

**`GET /studios/:studioId/appointment-statuses`**

```json
[
  { "value": "TENTATIVE", "label": "Предварительная бронь" },
  { "value": "BOOKED", "label": "Забронировано" },
  ...
]
```

Ответ `POST /landing/booking-request` при успешной записи по слоту:

```json
{
  "outcome": "booked",
  "message": "Запись создана. Мы свяжемся с вами для подтверждения.",
  "appointmentId": "apt_...",
  "clientId": "cli_..."
}
```

`outcome: "booked"` означает «заявка принята в CRM», **не** финальный статус `BOOKED`.

---

### UI — что исправить

#### 1. Журнал записей (сетка и список)

- Брать **`appointment.status` из API as-is** — не подменять на `BOOKED` для `createdSource === 'LANDING'`.
- Подпись статуса: из справочника или маппинг:

```typescript
const STATUS_LABELS: Record<string, string> = {
  TENTATIVE: 'Предварительная бронь',
  BOOKED: 'Забронировано',
  PENDING_CONFIRMATION: 'Ожидает подтверждения',
  AWAITING_PREPAYMENT: 'Ожидаем предоплату',
  ARRIVED: 'Пришёл',
  DONE: 'Завершено',
  CANCELLED: 'Отменено',
};
```

- **Цвет бейджа / блока в сетке** — `TENTATIVE` **отличается** от `BOOKED`:
  - `TENTATIVE` — жёлтый / янтарный (ожидает действия менеджера)
  - `BOOKED` — основной цвет записи (как сейчас)
- Если где-то захардкожено «Подтверждена» для всех новых записей — убрать.

Источники данных журнала (без изменений):

- `GET /studios/:studioId/appointment-log?date=YYYY-MM-DD`
- или `GET /studios/:studioId/appointments?date=YYYY-MM-DD`

#### 2. Модалка / карточка записи

- В селекте статуса **`TENTATIVE` должен быть доступен** и отображаться как «Предварительная бронь».
- Для **`MANAGER` / `ADMIN`**: явная кнопка или пункт «**Подтвердить запись**» →  
  **`PATCH /appointments/:id`** `{ "status": "BOOKED" }`  
  (показывать, когда `status === 'TENTATIVE'` и `createdSource === 'LANDING'` — опционально и для других `TENTATIVE`).
- После подтверждения обновить журнал и `bookedAt` подтянется с бэкенда.

#### 3. Лендинг — экран успеха (мелкая правка, если нужно)

Текст из `response.message` уже корректный. **Не** писать на success-экране «Запись подтверждена» — лучше:

- «Заявка принята» / «Предварительная запись создана»
- «Мы свяжемся для подтверждения»

Не менять логику submit — только формулировки, если сейчас написано «подтверждена».

#### 4. Уведомления (если есть)

Тип `NEW_APPOINTMENT` для мастера/менеджера — **без изменений**. В тексте уведомления не утверждать, что запись уже подтверждена; можно добавить бейдж «Предварительная» если показываете статус.

---

### Отличие от Nextbot

| Источник | Начальный статус | Кто подтверждает |
|----------|------------------|------------------|
| **Лендинг** (`LANDING`) | `TENTATIVE` | Менеджер в CRM → `BOOKED` |
| **Nextbot** (чат) | `TENTATIVE` (+ оплата / холд) | Свой сценарий Nextbot |
| **CRM вручную** | обычно сразу `BOOKED` | — |

Не смешивать с `AWAITING_PREPAYMENT` — это другой сценарий (предоплата в CRM).

---

### Чеклист

- [ ] В журнале записи с лендинга показывают **`TENTATIVE` / «Предварительная бронь»**, не «Забронировано».
- [ ] Цвет `TENTATIVE` визуально отличается от `BOOKED`.
- [ ] Менеджер может перевести `TENTATIVE` → `BOOKED` через `PATCH /appointments/:id`.
- [ ] На лендинге success-текст не обещает «уже подтверждено».
- [ ] Бэкенд и `POST /landing/booking-request` **не меняются**.

### Не делать

- Не переписывать форму записи на лендинге целиком (`LOVABLE_LANDING_BOOKING_FORM_PROMPT.md` — отдельная задача).
- Не вызывать Nextbot API с лендинга.
- Не ставить `BOOKED` на фронте «для красоты».
