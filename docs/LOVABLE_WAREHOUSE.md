# Склад: промпт для Lovable (интеграция с бэкендом)

## Обзор

В системе есть **единый (центральный) склад** и **склады филиалов**. Доступ и действия различаются.

- **Центральный склад** — видят и управляют только **владелец (OWNER)** и **заместитель владельца (DEPUTY_OWNER)**. Доступны: **Приход** (только здесь), **Добавить товар**, **Перемещение** в филиалы, **Изменить товар**, **Удалить товар**.
- **Склад филиала** — видят владелец, заместитель, менеджер (MANAGER), админ (ADMIN; только свой филиал). Доступны только: **Перемещение** (заказ с центра в этот филиал), **Списание**, **Изменить товар**, **Удалить товар**. Кнопок **«Приход»** и **«+ Добавить»** на складе филиала **не показывать** — приход и добавление товаров возможны только на основном (центральном) складе.

Единица измерения товара при добавлении выбирается из: **Кг** / **шт** / **мл** (в API: `KG`, `PCS`, `ML`).

---

## Поля товара

| Поле | Обязательное | Описание |
|------|--------------|----------|
| **Наименование** (name) | Да | Название товара |
| **Описание** (description) | Нет | Текст описания |
| **Артикул** (article) | Нет | Артикул / SKU |
| **Единица исчисления** (unit) | Да | `KG` (Кг), `PCS` (шт), `ML` (мл) |
| **Кол-во** (quantity / initialQuantity) | При добавлении на склад | Число (целое, ≥ 0). При создании товара можно указать начальное количество на складе. |

---

## Когда что показывать

1. **Раздел «Склад» в навигации**
   - **Владелец и заместитель:** пункт «Единый склад» (центральный) и возможность перейти к складу любого филиала.
   - **Менеджер, админ:** только «Склад» своего филиала (склад выбранной студии).

2. **Центральный склад (только OWNER, DEPUTY_OWNER)**
   - Таблица/карточки остатков: товар, количество, единица.
   - Кнопки: **Приход**, **Перемещение** (отправить на филиал), **Добавить товар**, **Изменить товар**, **Удалить товар** (удаление только если нигде нет остатков). Приход — только здесь: `POST /warehouse/central/receipt` с телом `{ "productId": "uuid", "quantity": 10 }`.

3. **Склад филиала**
   - Таблица/карточки остатков по выбранному филиалу.
   - Кнопки: **Перемещение** (запросить с центра в этот филиал), **Списание**, **Изменить товар**, **Удалить товар** (удаление только если на этом складе нет остатка). **Не показывать** кнопки «Приход» и «+ Добавить» — при попытке вызвать приход или добавление на филиале бэкенд вернёт 403.

## API: центральный склад

Базовый URL — ваш backend (например `https://yourapp.up.railway.app`). Все запросы с заголовком:  
`Authorization: Bearer <access_token>`.

### Получить центральный склад и остатки

```
GET /warehouse/central
```

**Ответ 200:**  
```json
{
  "id": "uuid-центрального-склада",
  "type": "CENTRAL",
  "stocks": [
    {
      "productId": "uuid-товара",
      "product": {
        "id": "uuid-товара",
        "name": "Воск для депиляции",
        "description": "Для чувствительной кожи",
        "article": "ART-001",
        "unit": "KG"
      },
      "quantity": 25
    }
  ]
}
```

### Список складов филиалов (для выбора «куда» при перемещении)

```
GET /warehouse/central/branches
```

**Ответ 200:**  
```json
[
  {
    "id": "uuid-склада-филиала",
    "type": "BRANCH",
    "studioId": "uuid-студии",
    "studio": { "id": "uuid-студии", "name": "Студия на Ленина" }
  }
]
```

### Список всех товаров (каталог)

```
GET /warehouse/central/products
```

**Ответ 200:** массив товаров  
```json
[
  {
    "id": "uuid",
    "name": "Воск для депиляции",
    "description": null,
    "article": "ART-001",
    "unit": "KG"
  }
]
```

### Добавить товар (на центральный склад)

```
POST /warehouse/central/products
Content-Type: application/json
```

**Тело:**  
```json
{
  "name": "Воск для депиляции",
  "description": "Для чувствительной кожи",
  "article": "ART-001",
  "unit": "KG",
  "initialQuantity": 10
}
```

- `description`, `article`, `initialQuantity` — необязательные.  
- `unit` — строго одно из: `KG`, `PCS`, `ML`.  
- `initialQuantity` — начальное количество на центральном складе (0, если не передано).

**Ответ 201:** объект созданного товара (id, name, description, article, unit).

### Приход на центральный склад

```
POST /warehouse/central/receipt
Content-Type: application/json
```

**Тело:**  
```json
{
  "productId": "uuid-товара",
  "quantity": 10
}
```

**Ответ 201:** `{ "success": true, "message": "Receipt recorded" }`.  
Приход возможен **только на основном (центральном) складе**. На складе филиала этот метод не вызывать — показывать кнопку «Приход» только на центральном складе.

### Изменить товар

```
PATCH /warehouse/central/products/:id
Content-Type: application/json
```

**Тело (все поля необязательные):**  
```json
{
  "name": "Новое название",
  "description": "Новое описание",
  "article": "ART-002",
  "unit": "PCS"
}
```

**Ответ 200:** обновлённый товар.

### Удалить товар

```
DELETE /warehouse/central/products/:id
```

**Ответ 200:** `{ "success": true }`.  
**Ответ 400:** если на каком-то складе ещё есть остаток (текст ошибки уточнит).

### Перемещение с центра на филиал

```
POST /warehouse/central/transfer
Content-Type: application/json
```

**Тело:**  
```json
{
  "toWarehouseId": "uuid-склада-филиала",
  "productId": "uuid-товара",
  "quantity": 5
}
```

**Ответ 201:** `{ "success": true, "message": "Transfer completed" }`.  
**Ответ 400:** недостаточно остатка на центральном складе (в сообщении будет доступное количество).

## API: склад филиала

Все маршруты вида: `/studios/:studioId/warehouse/...`  
`studioId` — ID студии (филиала), склад которого открыт.

### Получить склад филиала и остатки

```
GET /studios/:studioId/warehouse
```

**Ответ 200:**  
```json
{
  "id": "uuid-склада-филиала",
  "type": "BRANCH",
  "studioId": "uuid-студии",
  "stocks": [
    {
      "productId": "uuid-товара",
      "product": { "id": "...", "name": "...", "description": null, "article": null, "unit": "PCS" },
      "quantity": 3
    }
  ]
}
```

### Список товаров (для выпадающих списков при приходе/списании/перемещении)

```
GET /studios/:studioId/warehouse/products
```

**Ответ 200:** массив товаров (те же поля, что в каталоге центра).

### Добавить товар (на складе филиала — недоступно)

На складе филиала кнопку «+ Добавить» **не показывать**. Добавление товаров только на основном складе (`POST /warehouse/central/products`). Вызов `POST /studios/:studioId/warehouse/products` вернёт **403** с сообщением «Добавлять товары можно только на основном складе».

### Изменить товар

```
PATCH /studios/:studioId/warehouse/products/:productId
Content-Type: application/json
```

**Тело:** как у центра (частичное обновление: name, description, article, unit).  
**Ответ 200:** обновлённый товар.

### Удалить товар

```
DELETE /studios/:studioId/warehouse/products/:productId
```

**Ответ 200:** `{ "success": true }`.  
**Ответ 400:** если на этом складе ещё есть остаток.

### Перемещение с центра в этот филиал

```
POST /studios/:studioId/warehouse/transfer
Content-Type: application/json
```

**Тело:**  
```json
{
  "productId": "uuid-товара",
  "quantity": 5
}
```

**Ответ 201:** `{ "success": true, "message": "Transfer completed" }`.  
**Ответ 400:** недостаточно остатка на центральном складе.

### Приход (на складе филиала — недоступно)

На складе филиала кнопку «Приход» **не показывать**. Приход только на основном складе: `POST /warehouse/central/receipt`. Вызов `POST /studios/:studioId/warehouse/receipt` вернёт **403** с сообщением «Приход возможен только на основном складе».

### Списание

```
POST /studios/:studioId/warehouse/write-off
Content-Type: application/json
```

**Тело:**  
```json
{
  "productId": "uuid-товара",
  "quantity": 2,
  "forStaffUserId": "uuid-мастера"
}
```

`forStaffUserId` — обязательное поле: id пользователя с ролью **MASTER** этого же филиала (список брать из `GET /studios/:studioId/staff`, в UI оставить только мастеров).

**Ответ 201:** `{ "success": true, "message": "Write-off recorded" }`.  
**Ответ 400:** недостаточно остатка на складе; неверный мастер; ошибки валидации тела (в сообщении будет доступное количество или пояснение).

---

## Единицы измерения (unit)

В запросах и ответах использовать строки:

| Значение в API | Отображение в UI |
|----------------|------------------|
| `KG`           | Кг                |
| `PCS`          | шт                |
| `ML`           | мл                |

При добавлении/редактировании товара — выбор одной из трёх вариантов (Кг / шт / мл), при отправке на бэкенд — соответствующее значение `KG` / `PCS` / `ML`.

---

## Ошибки и ограничения

- **403 Forbidden** — нет прав (например, не владелец/зам зашли на центральный склад, или админ чужого филиала).
- **404 Not found** — неверный `studioId`, `productId` или `warehouseId`.
- **400 Bad request** — недостаточно остатка при перемещении или списании; попытка удалить товар с остатком; ошибки валидации тела запроса.

Удаление товара:
- Центр: возможно только если ни на одном складе нет остатка.
- Филиал: возможно только если на складе этого филиала остаток 0.

## Чеклист для Lovable

- [ ] Раздел «Склад» в меню: для владельца/зама — единый склад + выбор филиала; для менеджера/админа — только склад своего филиала.
- [ ] Экран центрального склада: остатки, кнопки «Приход», «Перемещение», «Добавить товар», «Изменить товар», «Удалить товар».
- [ ] Экран склада филиала: остатки, кнопки «Перемещение», «Списание», «Изменить товар», «Удалить товар». Не показывать «Приход» и «+ Добавить».
- [ ] Форма товара: наименование (обяз.), описание (необяз.), артикул (необяз.), единица — выбор Кг/шт/мл, при создании — начальное кол-во (необяз.).
- [ ] Перемещение с центра: выбор склада филиала (из `GET /warehouse/central/branches`), товар, количество.
- [ ] Перемещение на филиал: выбор товара (из `GET /studios/:studioId/warehouse/products`), ввод количества.
- [ ] Приход: только на центральном складе (POST /warehouse/central/receipt). Списание на филиале: выбор товара, ввод количества, **обязательный выбор мастера** (`forStaffUserId` из `GET /studios/:studioId/staff`, только `role === "MASTER"`); показывать доступный остаток и не давать списать больше.
- [ ] Обработка 400/403/404 и вывод понятных сообщений пользователю.
