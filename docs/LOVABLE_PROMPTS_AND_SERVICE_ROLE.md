# Роль SERVICE и настройки промптов

## Роль SERVICE

- В системе добавлена роль **SERVICE**.
- У неё **те же права, что и у владельца** (OWNER / DEPUTY_OWNER): доступ ко всем студиям, складам, дашборду, чёрному списку и т.д.
- Управлять самими владельцами и заместителями по-прежнему может только роль **OWNER**.

## Настройки промптов

Панель промптов доступна **только пользователям с ролью SERVICE**. Остальные роли не должны видеть раздел «Промпты» в настройках и не могут вызывать API промптов.

### Структура промпта

1. **Название (key)** — строка, **только латиница без пробелов** (допускаются буквы a-z, A-Z, цифры и подчёркивание `_`), макс. 128 символов.
2. **Описание (description)** — произвольный текст, **поддерживаются эмодзи**.

### API (все эндпоинты требуют авторизации и роль SERVICE)

| Метод | URL | Описание |
|--------|-----|----------|
| GET | `/prompts` | Список всех промптов |
| GET | `/prompts/:id` | Один промпт по id (UUID) |
| POST | `/prompts` | Создать промпт. Body: `{ "key": "welcome_message", "description": "Текст с эмодзи 👋" }` |
| PATCH | `/prompts/:id` | Обновить промпт. Body: `{ "key"?: string, "description"?: string }` |
| DELETE | `/prompts/:id` | Удалить промпт |

Ответы: стандартный JSON (объект промпта с полями `id`, `key`, `description`, `createdAt`, `updatedAt`). При ошибке доступа — 403.

### Промпт для Lovable

```
В настройках добавлен раздел «Промпты». Он виден и доступен только пользователям с ролью SERVICE. В разделе два блока: (1) название промпта — строго латиница без пробелов (буквы, цифры, подчёркивание); (2) описание промпта — произвольный текст с поддержкой эмодзи. API: GET/POST /prompts, GET/PATCH/DELETE /prompts/:id. Все запросы к промптам требуют роль SERVICE; иначе не показывать раздел и не вызывать API.
```
