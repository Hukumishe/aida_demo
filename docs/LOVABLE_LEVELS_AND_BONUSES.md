# Система уровней и бонусной программы — промпт для Lovable

---

## Промпт для Lovable (скопировать в чат)

Реализуй по ТЗ систему уровней клиентов и бонусов.

**1. Где что делать**

- **Присваивание уровня клиенту** — в **профиле (карточке) клиента**: отображение текущего уровня, кэшбэка и прогресса до следующего уровня; для клиента можно назначить уровень DIAMOND (только Владелец и Заместитель).
- **Настройки уровней и бонусов** — в **настройках приложения/студии**: глобальный лимит оплаты бонусами (%), включение/выключение начисления бонусов по услугам.

**2. В карточке клиента отображать**

- Текущий уровень: BRONZE | SILVER | GOLD | DIAMOND (из `client.level`).
- Текущий баланс бонусов: `client.bonuses` (1 балл = 1 ₸).
- Процент кэшбэка: `client.cashbackPercent` (приходит в ответе API).
- Прогресс до следующего уровня: из `client.levelProgress` — сколько уже оплачено деньгами (`currentTotalPaid`), сколько осталось до следующего порога (`remainingToNext`), название следующего уровня (`nextLevel`). Если уровень DIAMOND или максимальный — прогресс не показывать или показать «Максимальный уровень».
- **Прогресс-бар:** заполнение = `currentTotalPaid / nextLevelThreshold` (например, 10 000 / 50 000 = 20%). Текст «осталось X ₸» брать из `levelProgress.remainingToNext`.

Данные для этого приходят из **GET /clients/:id**: в ответе есть поля `level`, `levelSetManually`, `bonuses`, `cashbackPercent`, `levelProgress` (объект с `currentTotalPaid`, `nextLevel`, `nextLevelThreshold`, `remainingToNext`).

**Важно: обновление после завершения записи.** При завершении визита бэкенд сам пересчитывает уровень и сумму для прогресса (потраченная сумма после вычета бонусов засчитывается в `totalPaidForLevel`). Чтобы блок «Уровень лояльности» обновлялся автоматически, после вызова **POST /appointments/:id/done** обязательно заново запросить данные клиента: **GET /clients/:clientId** — и обновить состояние карточки клиента (в т.ч. уровень, прогресс-бар, «осталось X ₸»). Без повторного запроса клиента экран покажет старые данные.

**3. Назначение DIAMOND в карточке клиента**

- Кнопку «Назначить DIAMOND» показывать только **Владельцу и Заместителю**.
- По нажатию отправлять **PATCH /clients/:id** с телом: `{ "level": "DIAMOND", "levelSetManually": true }`.
- После успешного ответа обновить данные клиента (уровень и кэшбэк 30%).

**4. Настройки (раздел настроек студии/приложения)**

- **Глобальный лимит оплаты бонусами (0–100%)**  
  - Только для **Владельца** и Заместителя.  
  - Загрузка: **GET /studios/:studioId/settings** → в ответе `globalBonusPaymentLimitPercent`.  
  - Сохранение: **PATCH /studios/:studioId/settings** с телом `{ "globalBonusPaymentLimitPercent": 30 }` (число 0–100).

- **По каждой услуге: включить/выключить начисление бонусов**  
  - Только для **Владельца** и Заместителя.  
  - В списке услуг (или в редактировании услуги) поле «Начислять бонусы за услугу»: значение из `service.bonusAccrualEnabled`.  
  - Сохранение: **PATCH /studios/:studioId/services/:id** с телом `{ "bonusAccrualEnabled": true }` или `false`.

**5. История бонусов и ручная корректировка в карточке клиента**

- В карточке клиента вывести блок **«История бонусов»**: список записей из **GET /clients/:id/bonus-history**. Каждая запись: дата, тип (начисление/списание/ручная корректировка), сумма (`amount`: положительная — начисление, отрицательная — списание), при необходимости комментарий.
- **Ручная корректировка баланса** — только для **Владельца** и Заместителя: форма с полем «Сумма» (положительная или отрицательная) и опционально «Комментарий». Отправка: **POST /clients/:id/bonus-adjustment** с телом `{ "amount": 100, "comment": "Корректировка" }`. Не допускать отрицательный итоговый баланс (бэкенд вернёт 400).

**6. Уровни по ТЗ (для справки)**

- BRONZE — при регистрации, кэшбэк 3%.
- SILVER — 50 000 ₸ оплачено деньгами, кэшбэк 5%.
- GOLD — 120 000 ₸ оплачено деньгами, кэшбэк 10%.
- DIAMOND — только вручную (Owner/Deputy), кэшбэк 30%.

Расчёт уровня и начисление кэшбэка выполняет бэкенд при завершении услуги (DONE). На фронте достаточно отображать данные из API и давать возможность назначать DIAMOND и править настройки/историю по эндпоинтам выше.

## API (кратко)

| Метод | Путь | Описание |
|-------|------|----------|
| GET | /clients/:id | Карточка клиента (в т.ч. level, bonuses, cashbackPercent, levelProgress). |
| PATCH | /clients/:id | Обновление клиента; для DIAMOND: body `{ level: "DIAMOND", levelSetManually: true }` (Owner/Deputy). |
| GET | /studios/:studioId/settings | Настройки студии: `globalBonusPaymentLimitPercent`. |
| PATCH | /studios/:studioId/settings | Обновить настройки (Owner): body `{ globalBonusPaymentLimitPercent?: number }`. |
| PATCH | /studios/:studioId/services/:id | Обновить услугу (в т.ч. `bonusAccrualEnabled`). |
| GET | /clients/:id/bonus-history | История начислений/списаний бонусов. |
| POST | /clients/:id/bonus-adjustment | Ручная корректировка бонусов (Owner): body `{ amount: number, comment?: string }`. |
