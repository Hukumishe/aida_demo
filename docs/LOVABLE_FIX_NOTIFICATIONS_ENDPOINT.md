# Исправление ошибки 404 для эндпоинта /notifications/unread/count

## Проблема

Фронтенд обращается к эндпоинту `/notifications/unread/count`, который был удален с бэкенда. В логах видна ошибка:

```
GET /notifications/unread/count - 404
NotFoundException: Cannot GET /notifications/unread/count
```

## Задача

Нужно найти и исправить все места на фронтенде, где происходит обращение к эндпоинтам notifications, и либо удалить эти вызовы, либо закомментировать их, либо заменить на заглушку.

## Что нужно сделать

1. **Найти все обращения к `/notifications`**:
   - Поиск по кодовой базе: `notifications/unread/count`
   - Поиск по кодовой базе: `/notifications`
   - Поиск по кодовой базе: `fetch.*notifications`
   - Поиск по кодовой базе: `axios.*notifications`
   - Поиск по кодовой базе: `api.*notifications`

2. **Удалить или закомментировать следующие вызовы**:
   - `GET /notifications/unread/count` - получение количества непрочитанных уведомлений
   - `GET /notifications` - получение списка уведомлений
   - `POST /notifications` - создание уведомления
   - `PATCH /notifications/:id` - обновление уведомления
   - `DELETE /notifications/:id` - удаление уведомления
   - Любые другие эндпоинты, начинающиеся с `/notifications`

3. **Если есть UI компоненты для уведомлений**:
   - Скрыть или удалить компоненты, отображающие уведомления
   - Убрать иконки/бейджи с количеством непрочитанных уведомлений
   - Убрать меню/раздел уведомлений из навигации

4. **Если есть хуки или утилиты для работы с уведомлениями**:
   - Удалить или закомментировать хуки типа `useNotifications`, `useUnreadCount` и т.д.
   - Удалить или закомментировать функции API для работы с уведомлениями

5. **Обработка ошибок**:
   - Убедиться, что приложение не падает при отсутствии эндпоинта
   - Если есть try-catch блоки, убедиться, что ошибка 404 обрабатывается корректно

1. Проверить, что приложение запускается без ошибок

- **НЕ создавать** новые эндпоинты для уведомлений на бэкенде
