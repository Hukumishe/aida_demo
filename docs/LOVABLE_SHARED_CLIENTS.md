# Общая база клиентов — что поменять на фронте

Клиенты стали **общими для всех салонов**: одна база, один список. Бэкенд уже отдаёт единый список клиентов и не привязывает клиента к студии.

---

## Что изменить во фронтенде

1. **Не использовать `client.studioId` и `client.studio`**  
   В ответах API у клиента **больше нет** полей `studioId` и `studio`. Если в карточке клиента или в списке выводилось что-то вроде «Салон» / «Студия» — это нужно убрать или не показывать.

2. **Список клиентов**  
   `GET /studios/:studioId/clients` по-прежнему вызывается с `studioId` (для доступа), но возвращает **всех** клиентов, а не только «клиентов этой студии». Можно оставить заголовок просто «Клиенты» или «База клиентов», без привязки к названию салона.

3. **Создание клиента**  
   `POST /studios/:studioId/clients` не меняется. В ответе у созданного клиента **нет** `studioId` и `studio`. Не показывать и не сохранять их на фронте.

4. **Карточка клиента**  
   В профиле клиента (страница по `GET /clients/:id`) не выводить блок «Салон» / «Студия» и не использовать `client.studioId` или `client.studio` в логике.

5. **Остальное**  
   Сегменты, рефералы, черный список, записи, бонусы — API те же, меняется только то, что клиент не привязан к студии. Дополнительных правок не требуется.

---

## Промпт для Lovable (скопировать при необходимости)

```
Клиенты в системе общие для всех салонов: одна база. В ответах API у клиента больше нет полей studioId и studio. Нужно: (1) убрать из карточки клиента и из списка любой вывод «Салон»/«Студия» и не использовать client.studioId и client.studio; (2) список клиентов по GET /studios/:studioId/clients — это все клиенты, заголовок можно оставить «Клиенты»; (3) при создании клиента не ожидать в ответе studioId/studio.
```
