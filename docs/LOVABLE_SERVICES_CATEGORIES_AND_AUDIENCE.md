# Промпт для Lovable: категории услуг и аудитория (мужчины / женщины)

Скопируй блок ниже в чат Lovable как задание на реализацию.

---

## Задача

Доработать экраны **услуг** студии под новый API:

1. **Категории услуг** — отдельные сущности; их можно **создавать, переименовывать, менять порядок, удалять** (удаление только если нет услуг в категории).
2. Каждая **услуга обязательно принадлежит ровно одной категории** — при создании и редактировании услуги всегда выбирается категория.
3. У каждой услуги поле **аудитории**: только одно значение — **для мужчин** или **для женщин** (взаимоисключающий выбор: radio или один select с двумя опциями).

Базовый URL — тот же backend, что уже подключён. Авторизация: `Authorization: Bearer <token>`.  
Id в API **читаемые** (`sca_…`, `srv_…`), **не UUID**.

---

## API (уже на backend)

### Категории

| Действие | Метод | Путь | Тело / примечание |
|----------|--------|------|-------------------|
| Список | GET | `/studios/:studioId/service-categories` | — |
| Создать | POST | `/studios/:studioId/service-categories` | `{ "name": "Стрижка", "sortOrder": 0 }` — `sortOrder` опционально |
| Обновить | PATCH | `/studios/:studioId/service-categories/:categoryId` | `{ "name"?: "...", "sortOrder"?: number }` |
| Удалить | DELETE | `/studios/:studioId/service-categories/:categoryId` | 400, если к категории привязаны услуги |

Ответ категории: `id`, `studioId`, `name`, `sortOrder`, `createdAt`, `updatedAt`.

### Услуги (обновлённые поля)

**GET** `/studios/:studioId/services` — в каждой услуге:

- `categoryId` — строка (обязательна в данных).
- `category` — объект категории или вложенные поля (как отдаёт backend).
- `audience` — строка: **`MEN`** или **`WOMEN`** (enum).

**POST** `/studios/:studioId/services` — тело **обязательно** включает:

- `name`, `defaultDurationMin`, опционально `defaultPrice`, `requiredStaffCount`
- **`categoryId`** — id существующей категории этой студии (`sca_…`)
- **`audience`** — опционально; по умолчанию на backend **`WOMEN`**; лучше всегда отправлять явно: `"MEN"` или `"WOMEN"`

**PATCH** `/studios/:studioId/services/:serviceId` — можно сменить **`categoryId`** на другую категорию той же студии; **снять категорию нельзя** (не передавать `null`).

## UX / UI

1. **Раздел «Категории»** (или модалка / боковая панель): список категорий с сортировкой по `sortOrder`, затем по имени; кнопки «Добавить», «Редактировать», «Удалить». При удалении — если API вернул 400, показать сообщение: сначала перенести услуги в другую категорию.
2. **Форма услуги (создание / редактирование)**:
   - **Категория** — обязательный select: загрузить категории через `GET .../service-categories`. Если список пуст, показать подсказку: «Сначала создайте категорию» и кнопку перехода к созданию категории.
   - **Аудитория** — два варианта: «Для мужчин» / «Для женщин» → в API `MEN` / `WOMEN`.
3. **Список услуг**: отображать имя категории (из `category` или по `categoryId`), колонку «Аудитория» (человекочитаемо: М / Ж или «Мужчины» / «Женщины»).
4. Не фильтровать id по UUID; использовать значения из ответа API как есть.

## Проверка

- Создать категорию → создать услугу с этой категорией и аудиторией → в списке услуг всё отображается.
- Попытка удалить категорию с услугами — ошибка и понятный текст.
- Смена категории у услуги через PATCH работает.
