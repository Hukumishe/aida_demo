# День рождения клиента в карточке

---

## Промпт для Lovable (скопировать в чат)

Добавь в карточку клиента **день рождения** клиента.

**Отображение в карточке (просмотр):**
- В блоке с информацией о клиенте (имя, телефон, заметки) добавь строку **«День рождения»**.
- Значение брать из `client.birthDate` (приходит в ответе `GET /clients/:id`). Формат с бэкенда: ISO-строка, например `1990-05-15T00:00:00.000Z`. Отформатируй для пользователя (например, «15 мая 1990» или «15.05.1990»).
- Если `birthDate === null` или отсутствует — показывать «Не указан» или не показывать эту строку.

**Создание клиента:**
- В форму создания клиента добавь необязательное поле «День рождения» (`<input type="date">` или date picker).
- При отправке `POST /studios/:studioId/clients` передавай в теле поле `birthDate` строкой в формате **YYYY-MM-DD** (для `input type="date"` значение уже в этом формате). Если поле пустое — не передавай `birthDate`.

**Редактирование клиента:**
- В форму редактирования клиента добавь поле «День рождения»; предзаполняй из `client.birthDate` (для `input type="date"` передай дату в формате YYYY-MM-DD).
- При сохранении `PATCH /clients/:id` отправляй `birthDate`: строку YYYY-MM-DD или `null`, если пользователь очистил поле (чтобы сбросить день рождения на бэкенде).

**Важно:** API принимает и возвращает только формат даты **YYYY-MM-DD** (или ISO с датой). Никакого времени в интерфейсе не показывать.

---

## Задача (подробно)

Добавить в карточку клиента отображение и редактирование **дня рождения** клиента.

---

## API

### Ответ GET /clients/:id

В объекте клиента есть поле:

| Поле      | Тип     | Описание |
|-----------|---------|----------|
| `birthDate` | string (ISO) \| null | День рождения в формате ISO (`1990-05-15T00:00:00.000Z`) или `null`, если не указан |

На фронте для отображения достаточно взять дату (YYYY-MM-DD) или отформатировать локально (например, «15 мая 1990»).

### Создание клиента — POST /studios/:studioId/clients

В теле запроса можно передать:

```json
{
  "firstName": "Иван",
  "lastName": "Иванов",
  "phone": "+79991234567",
  "birthDate": "1990-05-15",
  "notes": "..."
}
```

- `birthDate` — опционально, строка **YYYY-MM-DD**.

### Редактирование клиента — PATCH /clients/:id

В теле запроса можно передать:

```json
{
  "birthDate": "1990-05-15"
}
```

Или `"birthDate": null` / не передавать поле, чтобы не менять. Чтобы очистить день рождения, передать `null` (если бэкенд поддерживает) или пустую строку — уточнить по ответу API.

---

## Что сделать на фронте

1. **Карточка клиента (просмотр)**  
   В блоке информации о клиенте вывести пункт «День рождения» и значение из `client.birthDate`, отформатированное по локали (например, «15.05.1990» или «15 мая 1990»). Если `birthDate === null` — не показывать блок или показывать «Не указан».

2. **Форма создания клиента**  
   Добавить необязательное поле «День рождения» (date input или date picker), значение отправлять в API как строку YYYY-MM-DD в поле `birthDate`.

3. **Форма редактирования клиента**  
   Добавить поле «День рождения»; при сохранении отправлять в PATCH текущее значение в формате YYYY-MM-DD или пустое значение для сброса (согласно поведению API).

4. **Список клиентов (по желанию)**  
   Можно вывести дату рождения в таблице/карточке списка (например, колонка «ДР» или иконка с тултипом).

---

## Валидация

- Формат на API: **YYYY-MM-DD** (только дата, без времени).
- На фронте для `<input type="date">` значение уже в формате YYYY-MM-DD — можно отправлять как есть.

---

## Чеклист

- [ ] В карточке клиента отображается день рождения (или «Не указан»).
- [ ] В форме создания клиента есть поле «День рождения» (опционально).
- [ ] В форме редактирования клиента можно изменить или очистить день рождения.
- [ ] В запросах POST/PATCH передаётся `birthDate` в формате YYYY-MM-DD.
