# Система ролей и прав доступа

## Обзор

В системе существует 4 роли пользователей с разными уровнями доступа:

1. **OWNER (Владелец)** - полный доступ ко всем функциям
2. **ADMIN (Админ)** - доступ только к своему филиалу
3. **MANAGER (Менеджер)** - удалённый сотрудник коллцентра, видит все записи и салоны
4. **MASTER (Мастер)** - видит только свои записи, ограниченный доступ

---

## 📋 Детальное описание ролей

### 1. OWNER (Владелец) 👑

**Доступ:**
- ✅ Полный доступ ко всем студиям
- ✅ Может выполнять любые действия
- ✅ Видит все данные всех студий
- ✅ Может создавать, редактировать, удалять любые сущности

**Ограничения:**
- ❌ Нет ограничений

---

### 2. ADMIN (Админ) 🏢

**Доступ:**
- ✅ Доступ только к своему филиалу (studioId должен совпадать)
- ✅ Видит всех клиентов своего филиала
- ✅ Видит все записи своего филиала
- ✅ Может создавать, редактировать клиентов своего филиала
- ✅ Может создавать, редактировать, отменять записи своего филиала
- ✅ Видит данные по своему филиалу (dashboard, статистика)

**Ограничения:**
- ❌ Не может видеть данные других филиалов
- ❌ Не может удалять клиентов (если есть endpoint удаления)
- ❌ Не может удалять записи (если есть endpoint удаления)

---

### 3. MANAGER (Менеджер) 📞

**Описание:** Удалённый сотрудник коллцентра

**Доступ:**
- ✅ Доступ ко всем студиям (как OWNER по доступу к студиям)
- ✅ Видит все записи всех салонов
- ✅ Может вносить записи в любую студию
- ✅ Может переносить записи
- ✅ Может отменять записи
- ✅ Может добавлять клиентов в любую студию
- ✅ Может редактировать клиентов

**Ограничения:**
- ❌ **НЕ может удалять** клиентов
- ❌ **НЕ может удалять** записи
- ❌ Не видит номер телефона клиента в записях (если требуется)

**Особенности:**
- Работает удалённо, поэтому нужен доступ ко всем студиям
- Основная функция - управление записями и клиентами

---

### 4. MASTER (Мастер) ✂️

**Доступ:**
- ✅ Доступ только к своему филиалу (studioId должен совпадать)
- ✅ Видит **только свои записи** (где staffUserId = userId мастера)
- ✅ Видит все данные в рамках своих записей **кроме номера телефона клиента**
- ✅ Может нажимать кнопки в своих записях (отметить прибытие, завершить и т.д.)
- ✅ Может бронировать **серое время** (busy slots) с объяснением причины
- ✅ Может создавать busy slots только для себя

**Ограничения:**
- ❌ Не видит номер телефона клиента
- ❌ Не может видеть список клиентов
- ❌ Не может создавать клиентов
- ❌ Не может редактировать клиентов
- ❌ Не может видеть записи других мастеров
- ❌ Не может создавать записи для других мастеров
- ❌ Может создавать busy slots только для себя

**Особенности:**
- Видит только свои записи
- Телефон клиента скрыт для защиты конфиденциальности
- Может бронировать серое время (вне рабочих часов) с обязательным комментарием

---

## 🔐 Логика проверки доступа

### Проверка доступа к студии

```typescript
// OWNER и MANAGER имеют доступ ко всем студиям
if (userRole === UserRole.OWNER || userRole === UserRole.MANAGER) {
  // Доступ разрешён
}

// ADMIN и MASTER могут получить доступ только к своей студии
if (userRole === UserRole.ADMIN || userRole === UserRole.MASTER) {
  if (userStudioId !== studioId) {
    throw new ForbiddenException('Access denied');
  }
}
```

### Фильтрация записей

```typescript
// MASTER видит только свои записи
if (userRole === UserRole.MASTER && userStaffId) {
  where.staffUserId = userStaffId;
}

// MANAGER видит все записи всех студий
// OWNER видит все записи всех студий
// ADMIN видит все записи своей студии
```

### Скрытие телефона клиента

```typescript
// Для MASTER скрываем телефон клиента
if (userRole === UserRole.MASTER) {
  return {
    ...appointment,
    client: {
      ...appointment.client,
      phone: undefined,
    },
  };
}
```

### Ограничение удаления для MANAGER

```typescript
// MANAGER не может удалять
if (userRole === UserRole.MANAGER) {
  throw new ForbiddenException('Managers cannot delete');
}
```

### Бронирование серого времени для MASTER

```typescript
// MASTER может бронировать серое время с комментарием
if (userRole === UserRole.MASTER && createBusySlotDto.comment) {
  // Пропускаем строгую проверку рабочих часов
  // MASTER может забронировать время вне расписания
}
```

## 🔌 API Endpoints и роли

### Endpoints для работы с записями

**GET /studios/:studioId/appointments**
- OWNER: все записи всех студий
- ADMIN: все записи своей студии
- MANAGER: все записи всех студий
- MASTER: только свои записи (фильтр по staffUserId), телефон клиента скрыт

**POST /studios/:studioId/appointments**
- OWNER: ✅
- ADMIN: ✅ (только для своей студии)
- MANAGER: ✅
- MASTER: ❌

**PATCH /appointments/:id**
- OWNER: ✅
- ADMIN: ✅ (только записи своей студии)
- MANAGER: ✅
- MASTER: ✅ (только свои записи)

**POST /appointments/:id/cancel**
- OWNER: ✅
- ADMIN: ✅ (только записи своей студии)
- MANAGER: ✅
- MASTER: ✅ (только свои записи)

**POST /appointments/:id/arrived**
- OWNER: ✅
- ADMIN: ✅ (только записи своей студии)
- MANAGER: ✅
- MASTER: ✅ (только свои записи), телефон клиента скрыт

**POST /appointments/:id/done**
- OWNER: ✅
- ADMIN: ✅ (только записи своей студии)
- MANAGER: ✅
- MASTER: ✅ (только свои записи), телефон клиента скрыт

- OWNER: ✅

## 💻 Реализация на Frontend

### Проверка роли пользователя

```typescript
// Получить роль из токена или контекста
const userRole = user?.role; // 'OWNER' | 'ADMIN' | 'MANAGER' | 'MASTER'

// Проверка прав доступа
const canDeleteClients = userRole === 'OWNER';
const canSeeAllStudios = userRole === 'OWNER' || userRole === 'MANAGER';
const canSeeClientPhone = userRole !== 'MASTER';
const canCreateClients = userRole !== 'MASTER';
```

### Условное отображение элементов UI

```typescript
// Показать кнопку удаления только для OWNER
{userRole === 'OWNER' && (
  <button onClick={handleDelete}>Удалить</button>
)}

// Скрыть телефон для MASTER
{userRole !== 'MASTER' && (
  <div>Телефон: {client.phone}</div>
)}

// Показать кнопку создания записи только для не-MASTER
{userRole !== 'MASTER' && (
  <button onClick={handleCreateAppointment}>Создать запись</button>
)}

// Показать селектор студии только для OWNER и MANAGER
{(userRole === 'OWNER' || userRole === 'MANAGER') && (
  <StudioSelector />
)}
```

### Фильтрация данных на Frontend

```typescript
// Для MASTER показывать только свои записи
const filteredAppointments = userRole === 'MASTER'
  ? appointments.filter(apt => apt.staffUserId === user.userId)
  : appointments;

// Скрыть телефон клиента для MASTER
const appointmentsWithHiddenPhone = userRole === 'MASTER'
  ? appointments.map(apt => ({
      ...apt,
      client: {
        ...apt.client,
        phone: undefined,
      },
    }))
  : appointments;
```

## ✅ Важные замечания

1. **Телефон клиента:** MASTER никогда не видит номер телефона клиента, даже в своих записях. Это сделано для защиты конфиденциальности.

2. **Серое время для MASTER:** MASTER может бронировать busy slots вне рабочих часов, но только если указан комментарий с объяснением причины.

3. **Удаление:** MANAGER не может удалять клиентов и записи, даже если есть соответствующие endpoints. Это ограничение должно быть проверено на backend.

4. **Доступ к студиям:** OWNER и MANAGER имеют одинаковый доступ к студиям (все студии), но MANAGER не может удалять данные.

5. **Список клиентов:** MASTER не может видеть список клиентов. Он видит клиентов только в контексте своих записей (без телефона).

6. **Создание записей:** MASTER не может создавать записи. Записи для мастера создаются администратором или менеджером.
